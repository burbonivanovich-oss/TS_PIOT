# Подтверждаемая отправка Git

`scripts/lib/git-push.mjs` принимает только уже committed delivery в чистом checkout с неизменными HEAD и веткой. Получатель задаётся явно: имя настроенного remote и полный `refs/heads/...`.

До отправки remote SHA должен совпадать с исходным коммитом прохода или его финальным metadata-коммитом; отсутствующая ветка допускается. Расхождение останавливает отправку. Используется обычный push без force. После отправки `ls-remote` должен подтвердить точный SHA. Повтор после потери ответа обнаруживает уже отправленный коммит и восстанавливает квитанцию без дополнительных коммитов.

Push-квитанция остаётся в Git metadata, чтобы её запись не делала отправленный checkout грязным. Сетевые ошибки не экспортируют stderr с потенциально секретным URL. Git вызовы ограничены 120 секундами и не запрашивают интерактивный пароль.

Владелец запускается с `daily.mjs --commit --push --remote origin --target-ref refs/heads/main`. Получатель должен соответствовать выделенному production checkout. Незавершённая отправка восстанавливается до следующего plan; без флага push pending-журнал блокирует новый цикл. Это команда для настроенного контура, текущий рабочий checkout ей не отправлялся.

Проверки используют настоящий локальный bare remote: успешная отправка и повтор, грязный checkout, некорректный ref, сторонний коммит на сервере и восстановление суточным владельцем без новой модели. Это доказывает поведение Git, но не GitHub-аутентификацию, запуск Actions или deployment. Расписание выключено. `deployed` всегда false.
