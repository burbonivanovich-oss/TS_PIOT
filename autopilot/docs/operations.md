# Эксплуатация Автопилота

Команды выполнять из корня `TS_PIOT-autopilot-runner`. Перед действием проверить [роли копий и нормы](engine-ownership.md), затем владельца и [порядок восстановления](runbook.md). Полный цикл выполняет одна рутина [auto-day](../../.agents/skills/auto-day/SKILL.md); отдельные plan/writer/settle не запускаются поверх daily.

## Диагностика

```bash
node autopilot/scripts/state.mjs get --json
node autopilot/scripts/run.mjs latest --json
node autopilot/scripts/health-check.mjs --json
node autopilot/scripts/metrics.mjs --json
node autopilot/scripts/interlink.mjs diagnose --json
```

`interlink diagnose` считает дефициты опубликованных файлов и причины отказа доноров: релевантность, потолок исходящих, отсутствие точного якоря, защищённые зоны. Он ничего не вставляет. Предложенный донор или dry-run не засчитываются как новая публичная входящая ссылка. Флаг interlinkExempt снимает только потолок исходящих; остальные требования сохраняются.

Приёмка, журнал выпуска, push и наблюдаемая публичная версия — разные результаты. Счётчики NEW/REWRITE и покрытие публичных квитанций смотреть отдельно. Неизвестный результат не заменять нулём. Сохранённое расписание не является доказательством запуска.

| Симптом | Проверка и действие |
|---|---|
| Нет новых нарядов | Проверить слоты, незавершённую доставку, отдельные месячные бюджеты, acceptedRepair и заполнение буфера. При запасе 14 обычное написание приостановлено; приёмка и календарный выпуск продолжаются |
| Принятое исправление ждёт | Проверить дневной потолок и календарный остаток REWRITE. Наличие исправленного кандидата не устраняет ошибку на сайте; недоступную ёмкость показать как открытый риск |
| Наряд без доставленного файла | Проверить живую модель и журнал попытки; восстанавливать тем же daily. Не освобождать слот или вызывать вторую модель только из-за тишины в выводе |
| Источники или evidence не проходят | Сверить актуальный текст, область нормы, hash и фрагмент источника. Не ослаблять пороги ради выпуска |
| Очередь выше 14 | Проверить историю и подтверждённые срочные factCorrections; исключение не снимает месячные, активные и дневные лимиты |
| Нет тем для refill | Проверить seeds и отказ дублей; не запускать refill параллельно владельцу |
| Гейты отклоняют многие тексты | Разобрать блокеры и исправить инструкцию/код. Повторный содержательный отказ ведёт в карантин; красные тесты останавливают контур |
| Недостаток входящих ссылок | Подобрать релевантных доноров и точные якоря. Черновики и формальные ссылки не засчитывать как исправление публичного графа |
| Скан дублей растёт | Содержательно проверить интенты и различающие признаки; пороги не менять ради исчезновения отчёта |
| Карантин больше 10 | Остановить контур и найти общую причину; не возвращать темы ручной правкой состояния |
| Норма недостижима третий проход | Проверить отдельные нормы и доступные слоты публикации, гейты, модель и расписание. Приёмка черновиков не компенсирует отсутствие выпуска |
| Push прошёл, сайт старый | Проверить конкретный deploy и публичный release.json; push не доказывает публикацию |
| Массовый неожиданный diff | Остановить владельца, проверить неразрушающую запись, восстановить проверенные версии по runbook |

## Восстановление

Расписание выключается до смены владельца. Дождаться терминального результата активного процесса и проверить lock/journal; отсутствие lock само по себе не выключает scheduler. Повреждённый lock не удалять вслепую. Прерванная доставка продолжается тем же daily без нового плана.

Сброс state, ручная правка счётчиков и `git checkout -- src/content/blog` не являются обычным ремонтом: они теряют учёт и могут уничтожить незавершённую работу. Вместо этого остановить контур, создать и проверить backup, восстановить в изолированной копии, сверить content и state, затем выполнить адресный revert/восстановление по runbook. Установленная рутина не переносится в чужой грязный checkout.

Для эксперимента нужна отдельная рабочая копия сайта с маркерами проекта, своим конфигом и состоянием. Один только CONTENT_ROOT с каталогом blog не создаёт валидную песочницу. Пример безопасного исследования — профильные тесты в изолированной ветке; production используется для чтения и штатной доставки проверенного результата.

## Ритм

| Когда | Результат |
|---|---|
| Ежедневно, одна рутина 09:00 | Штатный daily с восстановлением, гейтами, календарём и доставкой |
| Недельный аудит | Дубли, граф, карантин, темп и тесты; новое расписание не создаётся автоматически |
| После окончания месяца | NEW/REWRITE: принятые, журнал выпуска, публично подтверждённые и непроверенный остаток; не только state.history |
| При изменении порогов | Причина, исходное воспроизведение и отрицательные проверки; не менять пороги внутри прохода |

Движок, контент и состояние сохраняются согласованным Git-деревом. Локальный lock предотвращает конкуренцию на одном диске; независимые клоны не разделяют его, поэтому scheduler остаётся один. Старый K_Editor и ручные публикаторы не включаются как запасной исполнитель поверх Автопилота.
