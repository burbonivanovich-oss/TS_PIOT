# Эксплуатация: что делать, когда сломалось

Автономный контур ломается тихо. Он не падает — он продолжает работать
неправильно: пропускает через гейты что попало, крутит вариации одной темы,
зарастает сиротами. Симптом всегда один и тот же — «вроде работает, а
результата нет». Поэтому диагностика начинается не с логов, а с чисел.

```bash
node autopilot/scripts/health-check.mjs
```

## Таблица отказов

| Симптом | Причина | Что делать |
|---|---|---|
| `plan` выдаёт 0 нарядов при невыполненной норме | Слоты заняты зависшими нарядами | `state.mjs get` → `inFlight`. Наряд старше двух суток — статья не была написана, но слот занят. Запустить `settle`: он отметит `missing` и освободит слот |
| `refill` добавляет 0 тем | Генератор упёрся в потолок: всё, что он умеет собрать из seeds, уже написано или заблокировано как дубль | Добавить сущности в `autopilot/data/seeds.json`. Проверить `backlog.mjs stats` — если `blocked` в разы больше `accepted`, кластер исчерпан |
| Гейты заворачивают больше трети написанного | Инструкция автору расходится с проверкой | Смотреть, какая проверка чаще в блокерах. Чинить `.agents/skills/auto-write/SKILL.md`, **не порог** |
| Всё проходит гейты с первого раза | Гейт сломан, а не текст хорош | `npm test`. Отдельно проверить `sources` на кириллице: `\b` в JS не работает с кириллицей, и шаблоны молча перестают находить утверждения |
| Сирот больше 30% корпуса | Движку не за что зацепиться: у сирот нет якорей, встречающихся в чужих текстах | Переписывать **доноров**, а не сирот: добавить в подходящие статьи абзац, где сирота уместна |
| `dupes.json` растёт от прохода к проходу | Генератор приносит слишком близкие углы | Поднять `containmentBlock`, сузить шаблоны намерений в seeds |
| Карантин больше 10 тем | Отказ контура, а не список задач | Не разбирать поштучно. Найти общую причину: один и тот же блокер у большинства? |
| Норма месяца недостижима третий проход | Системный недобор | `state.mjs month`, сверить `done` и `expectedByToday`. Три причины по частоте: гейты, пустой бэклог, зависшие слоты |
| Diff по всему корпусу после прохода | Сломана неразрушающая запись | Немедленно остановить контур. `npm test` → тест «запись после чтения не меняет файл побайтно». Откатить корпус из git |

## Аварийные процедуры

**Остановить контур.** Снять рутины с расписания (`delete_trigger` или
отключить workflow). Скрипты сами по себе ничего не запускают.

**Сбросить состояние.** Счётчики месяца, слоты и карантин:

```bash
node autopilot/scripts/state.mjs reset --force
```

Написанные статьи не теряются — они в git принимающего репозитория. Теряется
только учёт: `done` за месяц обнулится, и норма дня пересчитается от нуля.

**Откатить перелинковку.** Отдельной команды нет и не будет: правки лежат в
git принимающего проекта.

```bash
git -C <contentRoot> checkout -- src/content/blog
```

Поэтому коммит после каждого прохода обязателен — без него откатывать нечего.

**Проверить движок, не трогая рабочий корпус:**

```bash
cp -R <contentRoot>/src/content/blog /tmp/sandbox/src/content/blog
CONTENT_ROOT=/tmp/sandbox AUTOPILOT_CONFIG=/tmp/sandbox/autopilot.config.json node autopilot/scripts/interlink.mjs apply
diff -r <contentRoot>/src/content/blog /tmp/sandbox/src/content/blog
```

## Ритуалы

| Когда | Что |
|---|---|
| Дважды в сутки | `/auto-day` — автоматически, по крону |
| Понедельник | `/auto-audit` — дубли, граф, карантин, темп, тесты |
| 1-е число | Посмотреть `state.mjs month`: `history` предыдущего месяца — единственная честная цифра выработки |
| При правке порогов | Записать в CHANGELOG что и почему. Через месяц причина не вспомнится, а число останется |

## Чего не делать

- **Не править `autopilot/data/*.json` руками.** Состояние меняется только скриптами.
  Ручная правка расходится с реальностью молча, и выяснится это через неделю.
- **Не ослаблять порог, чтобы прошёл конкретный текст.** Это одноразовая
  выгода против постоянного ухудшения: порог остаётся ослабленным навсегда,
  а текст всё равно был плохой.
- **Не запускать два прохода параллельно.** Слоты защищают от дублей внутри
  одного прохода, но `autopilot/data/autopilot.json` перезаписывается целиком — два
  процесса затрут правки друг друга.
- **Активным должен быть ровно один контур.** Локальные рутины на машине и
  облачные рутины — это две независимые копии состояния: у облака свой клон
  репозитория, у локали своя рабочая копия. Работая одновременно, они возьмут
  одни и те же темы из бэклога и напишут их дважды. Включая один контур,
  выключайте другой — не «на всякий случай оставим оба».
- **Не держать включённым старый редакционный контур K_Editor.** Он пишет в
  свой репозиторий, файлы не сталкиваются — но темы берёт из той же тематики,
  а проверка дублей Автопилота видит только корпус принимающего проекта и о
  черновиках K_Editor не знает. Две системы независимо напишут одно и то же.
