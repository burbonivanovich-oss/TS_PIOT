# Календарь выпуска 55 + 14

`publish.calendar: true` включает отдельные нормы `monthlyTarget` новых статей и `monthlyRewriteTarget` обновлений. На день D из N дней допускается накопленный выпуск `ceil(target × D / N)` каждого вида. Недобор остаётся доступным, но `publish.maxPerDay: 3` ограничивает общий суточный выпуск. Рерайты не отнимают месячный бюджет новых статей.

Решение основывается на журнале фактического локального выпуска `publish-log.json`, а не на счётчиках написания или приёмки. `days` содержит выпущенные slug, `kinds` различает виды по дате. Старые записи без вида считаются новыми консервативно. При повреждённом календаре приёмка останавливается и восстанавливает транзакцию.

Все даты считаются в UTC. При нескольких запусках остаток пересчитывается из сохранённого журнала. Старейшие принятые материалы выпускаются первыми в пределах бюджета своего вида; исчерпанный бюджет новых не блокирует доступный рерайт. Квота никогда не разрешает текст, не прошедший повторные гейты.

В этом режиме `scripts/release-next-draft.mjs` сайта не публикует: владелец выпуска — `autopilot/scripts/pipeline.mjs settle`. Старый workflow может запускаться, но выдаёт пустой slug и не меняет корпус. Перед включением рабочего расписания необходимо доказать выполнение цепочки plan → модель → settle → коммит целого состояния → деплой. Наличие календаря не доказывает, что этот исполнитель уже работает.

Проверено моделированием месяцев в 28, 29, 30, 31 день: при полном годном буфере выпускаются ровно 55 новых и 14 обновлений, общий лимит 3 в сутки соблюдается при четырёх запусках. Локальный выпуск и успешный деплой — разные события: live должен проверяться отдельно.
