# Подтверждение публичной версии

Сборка сайта создаёт `/release.json`: revision из реального Git HEAD, время сборки и sourceClean. При GitHub-сборке GITHUB_SHA обязан совпадать с HEAD. Dirty-сборка может использоваться для локальной приёмки, но её квитанция не подтверждает публичную версию.

`node autopilot/scripts/live-release.mjs --site https://etiketka-media.ru/ --commit <точный SHA> --pages <JSON-файл>` проверяет HTTP 200, JSON-квитанцию с точным SHA и sourceClean=true, затем HTML каждой ожидаемой страницы. JSON содержит массив объектов `path` и `requiredText`: для рерайта используйте уникальную изменённую фразу из тела, а не прежний общий заголовок. Без pages проверяется только версия сборки.

Редиректы, иной origin, не-HTML страница, отсутствующий текст, старая версия, dirty-сборка и ошибка HTTP дают отказ. Запросы используют параметр revision и no-cache; сетевой таймаут 20 секунд. Никакой push/merge или запись состояния этим read-only CLI не выполняется.

Это подтверждение публичной сборки и заданных страниц. Оно не заменяет содержательную приёмку, квитанцию GitHub Pages job или подтверждённые лиды/оплаты. В суточный CLI проверка deployment пока не включена.
