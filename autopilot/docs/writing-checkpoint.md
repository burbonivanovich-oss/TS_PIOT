# Доставка текста и возобновление

`node autopilot/scripts/writing-checkpoint.mjs status` показывает активные задания:

- write: нет доставленного результата текущей попытки; старый файл сам по себе не является доказательством.
- settle: есть квитанция, её хеш совпадает с текущими байтами и идентичность попытки не менялась; не писать повторно, запустить приёмку.
- closed: активного слота уже нет, не писать эту тему по старому наряду.

Исполнитель после фактического написания вызывает `record --slug <slug>`. Квитанция сохраняется в data/writing-receipts.json под общим lock: kind, claimedAt, failures/infraFailures, hash, runId и дата. Если все задания доставлены, записывается written. Повреждённый наряд, отсутствие файла, две версии md/mdx, выход за корпус, несовпадение слота и наряда или уже завершённая приёмка блокируют запись.

Квитанция означает доставку байтов, а не качество. Даже отклоняемый текст может быть доставлен; источник и смысл его фактов проверяют отдельные гейты. Не ставить квитанцию вместо работы модели. После отказа settle увеличивает номер попытки, старое доказательство больше не позволяет пропустить написание.

Планирование до приёмки сохраняет runId; plan после gated создаёт новый манифест для новой попытки, не записывая written после старого gated. Старая стадия built остаётся доказательством своей сборки; актуальный результат каждой сборки находится в отчёте текущего settle. Повтор самого settle не начисляет публикацию повторно.

Проверено CLI на изолированном корпусе: record сохраняет written без gated, status показывает settle. Проверены изменение байтов, новая попытка, закрытый слот, две версии файла и дубли наряда. Рабочий scheduler и live-возобновление ещё не доказаны.

В рабочем конфиге `gates.requireWritingReceipt: true`. Приёмка проверяет квитанцию перед гейтами каждого активного наряда. Отсутствующая квитанция, изменённые байты, другой вид работы или другая попытка считаются инфраструктурной недоставкой; существующий опубликованный файл рерайта при этом не получает hold и не засчитывается обновлением. После лимита недоставок слот освобождается. Очередь ранее принятых материалов проходит собственную повторную проверку качества.

Для старых тестовых конфигов ключ необязателен; без него историческое поведение сохраняется. Рабочий исполнитель не должен выключать его ради прохода приёмки. Квитанция не доказывает содержательную новизну рерайта: записывать её без фактической работы запрещено процедурой, качество и фактура проверяются дальше.
