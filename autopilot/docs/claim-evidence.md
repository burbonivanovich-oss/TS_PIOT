# Подтверждение утверждений первоисточниками

Перед приёмкой новых статей и обновлений исполнитель сохраняет
`autopilot/data/claim-evidence/<slug>.json`. Критические утверждения находятся
в `claims` результата `gates.mjs check --slug <slug> --json`; поле `sentence`
содержит точное предложение. Сам факт отказа гейта не мешает получить список.

Список охватывает тело и отображаемые поля frontmatter, включая FAQ. Ссылку
и evidence нужно сохранить для утверждения в каждом таком поле. Используй
`sentence` из результата гейта, а не отдельно извлечённую строку тела.

Для обычных полей `title`, `description`, `lead` и `summary`, где Markdown-ссылка
не отображается, допустима явная привязка в `claims`: `field` с точным именем
поля, `claimHash` текущего предложения и `source`. Для такой привязки обязательны
те же настоящий свежий снимок, точный фрагмент, дата сверки, `verified` и
объяснение применимости. Неоднозначные источники не выбираются автоматически.
Тело, таблицы и FAQ сохраняют требование ссылки в том же предложении:
доказательство заголовка их не подтверждает. Изменённый текст поля требует
новой сверки. Источник такой привязки входит в мониторинг и реестр корпуса.

Для каждого утверждения исполнитель получает настоящий документ, читает
подтверждающий фрагмент и проверяет смысл, актуальность нормы и область
применения. Он может удалить неподтверждённый факт вместо сохранения evidence.
Разрешённый домен, HTTP 200, маркер фактчека и числа в цитате не заменяют эту
работу. Запрещено придумывать снимок документа или подтверждающий фрагмент.

Снимок текстового первоисточника:

```bash
node autopilot/scripts/source-snapshot.mjs --url <URL>
```

Скрипт возвращает JSON с URL, конечным адресом, HTTP-статусом, временем,
полным извлечённым текстом и SHA-256. Он отказывает при ошибке, чужом
редиректе, пустом тексте или PDF. PDF требует отдельного реального извлечения
и сверки; недоступный документ не считается подтверждённым. Вывод скрипта
копируется в `documents` без изменения текста и контрольной суммы.

Формат файла:

```json
{
  "documents": ["объект, полученный source-snapshot.mjs"],
  "claims": [{
    "claimHash": "SHA-256 нормализованного sentence из гейта",
    "source": "точный URL первоисточника из утверждения",
    "excerpt": "дословный подтверждающий фрагмент сохранённого документа",
    "checkedAt": "время реальной проверки в ISO 8601",
    "result": "verified",
    "rationale": "почему документ подтверждает утверждение, к кому и когда норма применяется"
  }]
}
```

`documents` содержит объекты, а не строку из поясняющего примера. Для вычисления
идентификатора используется `claimHash` из `autopilot/scripts/lib/claim-evidence.mjs`.
Нормализация сохраняет слова ссылок, поэтому добавление внутренней ссылки
к существующему якорю не обесценивает сверку. Изменение слов утверждения,
его источника, даты или суммы требует повторной проверки.

Гейт требует свежий снимок с целой контрольной суммой, точное утверждение,
результат `verified`, объяснение и фрагмент из снимка. Даты и суммы должны
совпадать с фрагментом: короткая и полная запись даты, сумма словами и
эквивалентная сумма цифрами сравниваются по значениям. Для ссылок на нормы
проверяются числовые идентификаторы. Это детерминированная проверка
полноты и привязки evidence; семантическую достоверность обеспечивает реальная
сверка исполнителем. Одновременно действует QA сайта с его результатами
фактчека. Полноценный production-фактчек считается проверенным только после
контрольного материала с retained evidence и негативными примерами.


## Дата маркера QA сайта

Свежесть `.claude/factchecked/<slug>` проверяется по дате внутри файла,
не по mtime: Git checkout обновляет время файла. Пустой marker блокируется.
Старые форматы первой строки `YYYY-MM-DD`, ISO timestamp и
`Factcheck pass: YYYY-MM-DD` поддерживаются. JSON требует `passed: true`
и `checkedAt`. Будущая, невозможная или старше 180 дней дата не проходит.
Это дополнительная проверка срока, а не доказательство содержания фактов:
связка утверждение/документ/фрагмент по-прежнему обязательна.

Маркер QA и `src/data/factcheck/results/` входят в общий коммит со статьёй,
обложками и состоянием. Новый чистый раннер должен получить тот же evidence,
на основании которого текст был проверен локально.
