# Исполнитель суточного цикла — текущее состояние

03.10.2026. Модельный исполнитель ещё не подтверждён в рабочем расписании.

Корневой GitHub workflow выполняет только детерминированные plan/settle. Комментарий об отдельном scheduler не является доказательством его существования. Расписание workflow выключено до двух успешных canary. Старый публикатор уступает календарю; после деплоя этой версии без рабочего исполнителя новые статьи автоматически выходить не будут.

Локальные исправления: перед settle в чистом GitHub раннере `npm ci` устанавливает зависимости принимающего сайта для QA/build. Движок сохраняет нулевые runtime dependencies. В allowlist и коммит включены обложки и превью, чтобы статья не попала в удалённый корпус без локальных файлов изображения. Процедура auto-day выполняет preflight и тесты до планирования; при пустых нарядах принимает непустую очередь отложенного выпуска.

Для доказательства PUB-06 необходимо:

1. Один исполнитель всего цикла из авторитетного репозитория: plan → auto-write/auto-rewrite → settle → целый коммит → проверка деплоя. Две машины не должны писать в один checkout независимо.
2. Привязка runId и хешей файлов к результатам написания; наличие Markdown само по себе не значит, что модель закончила. Повтор после падения продолжает тот же наряд и не пишет принятую статью заново.
3. Стадии written/built/committed должны подтверждаться фактическими событиями. Стадия built теперь записывается после фактической финальной сборки вместе с временем, кодом и хешем корпуса; отчёт явно указывает отсутствие сборки. written теперь связан с квитанциями доставки и хешами файлов; это не приёмка качества. committed и полный рабочий исполнитель ещё не связаны с доказательствами. Нельзя выдавать наличие stage API за работающую цепочку.
4. Два настоящих canary с доказательствами источников, иллюстрациями, отрицательным случаем и проверкой отката; затем рабочее расписание один проход в сутки.
5. Первый недельный журнал и месячный отчёт: новые live-статьи отдельно от рерайтов, отсутствие дублей и обоснованное число остановок.

В текущем общем рабочем checkout есть независимые незакоммиченные изменения, а ветка fix/... не соответствует guard. Это не основание ослабить защиту или включить cron. Canaries следует выполнять в согласованной изолированной рабочей ветке с целой версией сайта и движка; незавершённые чужие изменения переносить автоматически нельзя.


04.10.2026: добавлен `scripts/writer.mjs` — мост нарядов к локальному Codex CLI. Запуск из корня сайта: `node autopilot/scripts/writer.mjs`, либо `npm run write` из autopilot. CLI перед моделью выполняет preflight и весь набор тестов. Модель и авторизация наследуются из установленного CLI; бинарник можно явно задать `AUTOPILOT_CODEX_BIN`. Движок не устанавливает CLI и сохраняет нулевые dependencies.

Общий lock удерживается на время написания и записи квитанции (reentrant в родительском процессе). Повтор пропускает доставленные и закрытые наряды. Структурированный итог сверяется с текущими slug, attempt и SHA256; неизменённый рерайт, изменённые orders/счётчики, ошибка/таймаут процесса или отсутствующий бинарник не получают квитанцию. После сбоя исполнитель прекращает следующие модельные вызовы; settle отдельно учитывает инфраструктурные ошибки и проверяет качество.

Тест реального пути моста и writing-checkpoint выполнен с детерминированным подставным исполнительным вызовом: квитанция записана, повтор не вызывает исполнителя. Это проверка механизма, **не модельный canary**. Работа Codex CLI с реальной авторизацией, поиском, генерацией иллюстрации, целым коммитом и production-доставкой пока не доказана. Ограничения модели в prompt не являются файловой изоляцией; перед production требуется проверка состава всех её изменений. Существующий GitHub workflow не вызывает этот мост и расписание остаётся выключенным.


04.10.2026, откат написания: перед каждой попыткой создаётся отдельный durable `.writer-journal` для корпуса, JSON состояния/манфестов, claim-evidence, обложек/превью, фактчека и research. При исключении либо неверном результате восстанавливаются исходные байты и удаляются новые файлы в этих областях. Посторонняя статья/артефакт или правка состояния в снимке отклоняются до квитанции. Журнал незавершённого writer блокирует settle из другого процесса. Повтор writer восстанавливает журнал под общим lock до чтения нарядов; CLI делает восстановление до preflight. Перед вызовом модели проверяется открытый манифест.

243 теста прошли: инъекция частичной записи/исключения, посторонняя статья, SIGKILL процесса, восстановление источника и иллюстрации, блокировка settle и повтор доставки. SIGKILL-тест не запускает модель и не проверяет оставшиеся живые дочерние процессы CLI. До реального model canary необходимо обеспечить завершение этих процессов перед откатом и защитить код вне перечисленных областей. Размер текущих hero/preview около 151 MiB; журнал включает их, поэтому скорость реального прохода ещё нужно измерить. Авторизация установленного CLI через ChatGPT подтверждена `codex login status`, но работа модели не проверена.


04.10.2026, проверка живого CLI: введён supervisor POSIX process group с отдельным worker. До отправки prompt сохраняется actor lease; отдельный daemon CLI выключен. При нормальном завершении/таймауте группа завершается, и до квитанции/отката проверяется её отсутствие. Живая либо непроверяемая группа оставляет lease и запрещает восстановление. Проверены настоящие дочерние процессы, продолжающие писать после выхода родителя, таймаут и живая lease. Windows-модельный мост пока не поддержан; детерминированный движок остаётся Node-only.

Снимок расширен на исходный код и артефакты текущего slug. Посторонняя правка кода отклоняется и откатывается. Git internals, dependencies/build outputs и env-файлы вне снимка; модель запускается в workspace-write, и canary проводится в отдельном checkout. При реальном корпусе JSON с base64 превысил лимит строки Node: writer теперь использует бинарные файлы резервной копии и компактный журнал v2. Целостность всех резервных файлов проверяется до первой мутации восстановления; неизменённые файлы не перезаписываются. В Git исключены journal, backups, lease и приватные диагностические записи.

Полный набор 247 тестов прошёл. Реальный Codex CLI gpt-6.1-sol/low совершил 14 вызовов shell, написал черновик и запустил гейты. Самопроверка нашла два блокера сайта: отсутствующий CpaCallout и маркер фактчека. Затем sampling stream прерывался с TLS IO errors; 30-минутный таймаут остановил группу и откатил попытку. Доставки и публикации нет, счётчики не увеличились. Raw trace хранится локально и не экспортируется. Skill дополнен контрактом сайта до первой самопроверки; failed теперь требует конкретную причину, а законченная отвергнутая гейтами попытка передаётся в settle как доставка, не как разрешение выпуска. Следующий model canary всё ещё обязателен.

Сеть workspace-write включена точечно для получения первоисточников по [официальной конфигурации Codex CLI](https://learn.chatgpt.com/docs/agent-approvals-security#network-access); source-snapshot сохраняет собственную allowlist. Расписание и production остаются выключенными.


Добавлен `node autopilot/scripts/daily.mjs` (`npm run daily`): один процесс удерживает общий reentrant lock от чтения текущего прохода до settle/build. CLI восстанавливает writer и выполняет preflight/тесты до цикла. Внутри lock восстанавливается и журнал settle. Новый проход проверяет источники и планирует; незакрытый продолжает прежний runId без повторного plan; уже gated не начинает новый материал до committed. Ошибка writer, которая безопасно откатилась, идёт в settle для учёта инфраструктурной попытки; живая группа/небезопасный откат прерывают цикл до settle.

Статус `delivery_pending` — явный незавершённый участок: адаптер целого коммита, push/deployment и live-read-back ещё отсутствует. Раннер не ставит committed и не активирует расписание. Пять проверок координатора включают настоящий вызов владельца на файловом манифесте; фактический полный модельный прогон через daily пока не выполнен. Отказ второго владельца проверен против живого модельного writer в изолированном checkout.


Git-адаптер подключён к `daily.mjs --commit`. Чистая точка фиксируется до новых source-monitor/plan; попытка задним числом присвоить её уже изменённому проходу запрещена. Незавершённые Git-объекты возобновляются прежде чтения стадии committed для нового планирования. Без флага коммита вернётся git_delivery_pending. Пустой проход сохраняет лишь состояние при совпадающем исходном корпусе, не выдумывая build. Проверка настоящего daily-owner в отдельном Git-репозитории восстановила подготовленную доставку, сохранила build-output и получила чистый checkout без нового вызова модели. Это fixture с небольшим тестовым build, не полный Astro/model/production-проход. Push/deployment/scheduler пока не подключены.
