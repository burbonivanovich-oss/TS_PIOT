# Восстановление незавершённой приёмки

`pipeline.mjs settle` под общим lock сохраняет `data/.settle-journal` до первой правки. Журнал содержит исходные байты и права Markdown/MDX корпуса, корневых JSON состояния и JSON манифестов `data/runs/`. Источники доказательств, lock и независимые вложенные данные не откатываются.

После выпуска, перелинковки и успешной сборки записываются счётчики и отчёт. Файлы синхронизируются на диск, затем удаляется журнал. При исключении выполняется откат; после аварии следующий `plan` или `settle` восстанавливает журнал перед своей работой. `settle --dry` при незавершённом журнале останавливается без восстановления. Обработку старого lock выполняет существующая защита lock, восстановление её не обходит.

Контрольная сумма, привязка к реальным корням, допустимые расширения, область путей и отсутствие симлинков/hardlink проверяются до записи. Повреждённый журнал оставляется для расследования, а цикл останавливается. Нельзя вручную удалить журнал, чтобы продолжить с частично изменённым корпусом.

Проверено: SIGKILL после изменения статьи, восстановление другим процессом, сохранение успешного результата после commit, восстановление байтов состояния и манифеста, удаление нового отчёта, отказ на checksum/path traversal. Реальное отключение питания не воспроизводилось. Механизм рассчитан на одного владельца файлов под lock; внешняя параллельная запись в корпус не поддерживается.

Журнал локальный и исключён из Git. Облачный раннер с новым клоном восстанавливается из последнего целого коммита, а не из локального журнала другой машины. Неуспешную сборку нельзя отправлять в деплой; восстановление директории сборки этим механизмом не выполняется.
