# AGENTS.md — автономный контент-контур «Автопилот»

Единственный источник правил проекта для Codex.

## Что это

Производственный контур, который сам делает контент для принимающего проекта:
выбирает темы, отсекает дубли, пишет статьи, регулярно переписывает старые и
поддерживает перелинковку. **Согласований нет.** Ни плана, ни отдельной
статьи, ни правок — никто не подтверждает.

Цель — **200 статей в месяц** при том, что каждая опубликованная статья
проходит те же проверки, которые в редакционном контуре делал человек.

Родословная: это переработка `K_Editor` — модуля-помощника редактора, где
цикл шёл через Google Drive и человеческие шлюзы (согласование плана в ячейке
B2, «принято» по каждой статье, потолок очереди вычитки 6 штук → ~26 статей в
месяц). Здесь все шлюзы заменены детерминированными гейтами.

### Чем это отличается от Editor

| | Editor (K_Editor) | Автопилот |
|---|---|---|
| Кто решает, что писать | Редактор согласует план | Планировщик + проверка дублей |
| Кто принимает текст | Редактор в Google Doc | `scripts/gates.mjs` |
| Что ограничивает выработку | Скорость вычитки человеком | Слоты и норма дня |
| Выработка | ~26 статей/мес | 200 статей/мес |
| Рабочее место | Google Drive | Файлы репозитория |
| Рерайты | По остаточному принципу | Плановая доля выработки (25%) |
| Перелинковка | Вручную при написании | Движок по всему корпусу каждый проход |
| Роль человека | Внутри цикла, на каждой статье | Снаружи: пороги, seeds, разбор карантина |

Google Drive, доки, комментарии, кнопка редактора, `drive-sync.mjs`, состояния
`awaiting_review` — **удалены целиком**, а не отключены флагом. Всё это
существовало только ради человека внутри цикла.

## Главный принцип

**Автономность держится на отказах, а не на разрешениях.** Контур, который
всё пропускает, за месяц производит 200 единиц мусора и убивает домен. Поэтому:

- сомнительная тема **не пишется** (проверка дублей — блокирующая, не
  предупреждающая);
- не прошедший гейты текст **не публикуется**, даже если норма дня не выбрана;
- дважды не прошедшая тема уходит **в карантин**, а не на третий круг;
- никакой шаг не «чинится» ослаблением порога по ходу прохода.

Цена ошибки несимметрична: незаписанная статья стоит одного слота, плохая
статья в выдаче — доверия ко всему домену и тянет за собой соседей.

## Стек

- Node.js без зависимостей. `node autopilot/scripts/<имя>.mjs` работает везде, где есть
  Node ≥ 20. `package.json` не имеет `dependencies` — это не экономия, а
  требование: контур должен запускаться в любом раннере без установки.
- Языковая модель нужна ровно в одном месте — написание текста
  (`.agents/skills/auto-write/SKILL.md`, `.agents/skills/auto-rewrite/SKILL.md`). Всё остальное
  детерминировано и воспроизводится запуском скрипта.
- Контент принимающего проекта — Markdown/MDX в `src/content/blog/`.
  Путь задаётся `contentRoot` в конфиге или переменной `CONTENT_ROOT`.
- **Движок вложен в репозиторий сайта** (`autopilot/` внутри TS_PIOT), а не
  вынесен отдельно: облачной рутине тогда нужен один источник, статьи и
  состояние контура едут одним коммитом, и не бывает состояния, разъехавшегося
  с корпусом. Скиллы лежат в корневом `.agents/skills/` и исполняются
  из корня репозитория.

```

  dupes.json          взаимные пересечения корпуса

  state.mjs           машина состояний, счётчики, слоты, карантин
  backlog.mjs         генератор тем с фильтром дублей

  rewrite-queue.mjs   ранжирование кандидатов на рерайт
  interlink.mjs       граф ссылок: graph / plan / apply
  gates.mjs           гейты качества (замена редактора)
  health-check.mjs    единый отчёт о состоянии контура
```

## Цикл

```
      ┌──────────────── раз в сутки, по крону ────────────────┐
      ▼                                                       │
  pipeline.mjs plan                                           │
   ├ backlog.mjs refill      темы, прошедшие проверку дублей  │
   ├ rewrite-queue.mjs build ранжирование старого             │
   ├ state.mjs capacity      норма дня с учётом долга         │
   └ занимает слоты          → data/orders.json               │
      ▼                                                       │
  $auto-write × N   $auto-rewrite × M      ← единственный          │
      ▼               (модель пишет текст)    шаг с моделью   │
  pipeline.mjs settle                                         │
   ├ gates.mjs         прошло → draft: false, не прошло → назад│
   ├ 2 неудачи         → карантин                             │
   ├ interlink.mjs apply   перелинковка по всему корпусу      │
   └ счётчики месяца   → data/report-<дата>.json ─────────────┘
```

Раз в неделю поверх — `$auto-audit`: дубли, граф, карантин, темп, тесты.

## Учёт дублей

Четыре независимых сигнала, каждый ловит свой класс (`scripts/dedupe.mjs`):

1. **canonical** — совпадение отсортированных стемов заголовка. Ловит
   перестановочные дубли: «Кто обязан подключить X» ↔ «X: кто обязан подключить».
2. **containment** — взвешенное по IDF покрытие: все различающие слова темы
   уже есть в существующей статье. Основной сигнал.
3. **keyword-cannibalization** — покрытие целевых запросов. Ловит случай, когда
   заголовки разошлись, а в выдаче статьи конкурируют между собой.
4. **shingles** — совпадение тел по 5-словным окнам. Работает на готовом
   тексте (`scan`, гейт `duplication`), не на теме.

**IDF обязателен.** Без него в узкой тематике «маркировка игрушек» и
«маркировка косметики» дают сходство 0.71 — то есть дубль там, где две разные
товарные группы. Общее слово тематики должно весить мало.

Вердикты: `block` — тема не попадает в план вообще; `warn` — пишется, но с
обязательным сужением угла и ссылкой на пересекающийся материал (это уходит в
наряд); `ok` — без ограничений.

## Пропускная способность

| Параметр | Значение | Где менять |
|---|---|---|
| Норма месяца | 200 | `throughput.monthlyTarget` |
| Проходов в сутки | 2 | cron рутины |
| Слотов одновременно | 8 | `throughput.maxParallelWriting` |
| Доля рерайтов | 25% | `mix.rewrite` |
| Догоняющий коэффициент | 1.35 | `throughput.catchUpFactor` |

Норма дня — не «200/30», а догоняющая: недобор вчера повышает норму сегодня.
Иначе один сбойный день навсегда съедает месячную цель. Верхняя граница
догона тоже задана — иначе после недели простоя контур попытается выдать
пятьдесят статей за сутки и завалит гейты.

**Слот занимается при выдаче наряда, а не по факту написания.** Это защита от
повторного прогона крона: иначе два запуска подряд выдают один наряд дважды и
получаются две статьи на одну тему — ровно тот дубль, который весь контур и
предотвращает.

## Гейты

`scripts/gates.mjs`, 8 проверок, взвешенный балл 0–100, порог 70.

Блокеры (не компенсируются баллами): `frontmatter`, `length`, `sources`,
`links-valid`. Плюс отдельная проверка `duplication` по телу текста.

Ключевой — **`sources`**: каждая дата вступления в силу, сумма штрафа и ссылка
на норму должны опираться на первоисточник (`publication.pravo.gov.ru`,
`consultant.ru`, `garant.ru`, `nalog.gov.ru`, `честныйзнак.рф`, `crpt.ru`).
В контуре без человека проверять факты постфактум **некому**.

## Перелинковка

`scripts/interlink.mjs` — граф внутренних ссылок по всему корпусу, каждый
проход.

Правила: якорь — точное вхождение фразы в тексте (никаких «читайте также
здесь»); одна новая ссылка на абзац; 3–8 исходящих на статью; приоритет —
статьям с наименьшим числом входящих; взаимные ссылки штрафуются.

**Якоря фильтруются по IDF.** Якорь «маркировка» встречается в половине
корпуса и ведёт читателя куда попало — ссылка формально валидная и
бесполезная. Проходят либо фразы из двух и более слов, либо одиночные редкие
термины.

Хаб-страницы (календари, обзоры-указатели) осмысленно ссылаются больше нормы.
Для них в frontmatter ставится `interlinkExempt: true` — потолок исходящих
перестаёт к ним применяться и в гейтах, и в очереди рерайтов. Без этого флага
календарь маркировки с восемнадцатью ссылками всплывал бы в аудите каждую
неделю, и сигнал перестали бы читать.

Правка тела **не пересобирает frontmatter**: пишется исходный текст заголовка
байт в байт. Свой YAML-дампер не знает про списки объектов (`faq`) и молча их
сплющит, а тело статей правится регулярно.

## Соседство с автоматикой сайта

В принимающем репозитории уже работает `auto-publish.yml`: четыре раза в сутки
берёт старейший файл с `draft: true` и снимает флаг **без единой проверки**.
Для автопилота это дыра в гейтах — завёрнутый текст остаётся черновиком и был
бы опубликован через несколько часов, причём именно тот, что проверку не
прошёл.

Поэтому приёмка помечает завёрнутое полем `autopilotHold: true`, а
`scripts/release-next-draft.mjs` такие файлы пропускает. Маркер снимается сам,
когда статья проходит гейты со второго захода. Правя любой из этих двух
файлов, помните про второй.

## Что делает человек

Ничего внутри цикла. Снаружи — четыре вещи:

1. **Пороги** в `autopilot/config/autopilot.config.json` — если гейт систематически
   заворачивает годное или пропускает негодное.
2. **`autopilot/data/seeds.json`** — сущности, намерения, сегменты, календарь НПА.
   Генератор тем работает от них; когда бэклог перестаёт пополняться, ответ
   здесь.
3. **Карантин** — раз в неделю, по `$auto-audit`.
4. **Реакция на остановку** — контур сам останавливается и зовёт, когда
   сломан конфиг, недоступен репозиторий, карантин больше 10 тем или норма
   недостижима третий проход подряд.

## Запуск в Codex

Процедуры находятся в `.agents/skills/` и вызываются как `$auto-day`,
`$auto-audit`, `$auto-write` и `$auto-rewrite`. Для расписания использовать
локальные автоматизации Codex либо существующий `.github/workflows/autopilot.yml`.
Если суточный проход не нашёл нарядов, он завершается без уведомления.

## Тесты

```bash
npm test
```

Держат инварианты, которые ломаются незаметно и дорого: неразрушающую запись
frontmatter, срабатывание гейтов на кириллице, невозможность взять одну тему
дважды, работу IDF. **Красный тест — стоп контуру:** автопилот с испорченной
записью файлов за сутки разложит весь корпус.
