# Коммерческая воронка: события и границы доказательства

Локальная реализация 03.10.2026. Цели добавлены в декларативный список `src/data/metrika/goals.json`; синхронизация с кабинетом не выполнялась. Приём событий в рабочем счётчике не доказан.

| Событие | Что показывает | Чего не доказывает |
|---|---|---|
| product-view | Открытие страницы продукта | Просмотр всех блоков или покупку |
| product-cta-click | Клик на подключение: lead или external | Оплату по внешней ссылке |
| selector-task | Выбранную задачу | Пригодность решения |
| selector-result | Полученный результат, роль/форму бизнеса | Принятую заявку |
| selector-product-click | Переход из подбора к продукту | Подключение |
| form-start | Фокус на поле формы | Заполнение всех полей |
| form-submit-attempt | Событие submit | Успешный приём сервером или оплаченный заказ |

Ранее виджет отправлял `lead-*` на submit. Этот сигнал не был подтверждённым лидом. Новый код не отправляет его, а фиксирует form-submit-attempt. Исторические goal id оставлены в декларации и помечены пояснением; старые и новые периоды нельзя объединять под метрикой успешных лидов.

Параметры ограничены известными id офферов, задачами, ролями, формой бизнеса и типом перехода. Значения полей, телефон, email, ИНН, текст статьи, URL и query не передаются. Ошибка счётчика не должна блокировать подбор или переход. Для localhost/127.0.0.1/IPv6 loopback новые события отключены, чтобы проверки не создавали рабочую статистику.

Подтверждённый лид требует документированного сигнала успешного приёма от виджета или сверки партнёрского кабинета. Оплата и выплата — данные кабинета, не клики. До появления таких данных коммерческий отчёт должен показывать отсутствие подтверждения, а не нулевую/успешную конверсию.

Следующая приёмка COM-05: проверить реальные цели счётчика, рабочую доставку после деплоя, разрешённый сигнал успеха виджета, экспорт с одинаковым периодом и атрибуцией, базовый уровень конверсии и эксперимент. Форма не отправлялась при локальной проверке.
