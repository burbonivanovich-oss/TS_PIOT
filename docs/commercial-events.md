# Коммерческая воронка: события и границы доказательства

Локальная реализация 03.10.2026. Цели добавлены в декларативный список `src/data/metrika/goals.json`; синхронизация с кабинетом не выполнялась. Приём событий в рабочем счётчике не доказан.

Новые события выключены по умолчанию. После сохранения семи целей счётчика 109130279 включить `PUBLIC_COMMERCIAL_EVENTS_ENABLED=true` в окружении сборки и проверить доставку на рабочем сайте. Сборка без этого явного значения не отправляет новые коммерческие события. Проверки на localhost остаются отключены даже с флагом.

| Событие | Что показывает | Чего не доказывает |
|---|---|---|
| product-view | Открытие страницы продукта | Просмотр всех блоков или покупку |
| product-cta-click | Клик на подключение: lead или external | Оплату по внешней ссылке |
| selector-task | Выбранную задачу | Пригодность решения |
| selector-result | Полученный результат, роль/форму бизнеса | Принятую заявку |
| selector-product-click | Переход из подбора к продукту | Подключение |
| form-start | Фокус на поле формы | Заполнение всех полей |
| form-submit-attempt | Событие submit | Успешный приём сервером или оплаченный заказ |

Ранее виджет отправлял `lead-*` на submit. Этот сигнал не был подтверждённым лидом. Новый код не отправляет его, а фиксирует form-submit-attempt. Исторические goal id оставлены в декларации и помечены пояснением; старые и новые периоды нельзя объединять под метрикой успешных лидов.

Параметры ограничены известными id офферов, задачами, ролями, формой бизнеса и типом перехода. Значения полей, телефон, email, ИНН, текст статьи, URL и query не передаются. Ошибка счётчика не должна блокировать подбор или переход. Для localhost/127.0.0.1/IPv6 loopback новые события отключены, чтобы проверки не создавали рабочую статистику.

Подтверждённый лид требует документированного сигнала успешного приёма от виджета или сверки партнёрского кабинета. Оплата и выплата — данные кабинета, не клики. До появления таких данных коммерческий отчёт должен показывать отсутствие подтверждения, а не нулевую/успешную конверсию.

Следующая приёмка COM-05: проверить реальные цели счётчика, рабочую доставку после деплоя, разрешённый сигнал успеха виджета, экспорт с одинаковым периодом и атрибуцией, базовый уровень конверсии и эксперимент. Форма не отправлялась при локальной проверке.


4 октября: семь JS-целей созданы существующим GitHub workflow и прочитаны обратно в счётчике 109130279. Коммерческие события включаются в production-сборке через PUBLIC_COMMERCIAL_EVENTS_ENABLED=true. Отправка попытки формы по-прежнему не подтверждает лид, оплату или выплату. Две прежние цели глубины/времени исправлены на API depth/visit_duration; истории существующих целей не удаляются.


## Коммерческий отчёт и экономика

`node autopilot/scripts/commercial-report.mjs --days 7 --json` строит окно из ровно семи календарных дат включительно, в UTC. Данные текущего дня являются срезом на указанное `asOf`, а не обещанием итогов за полный день.

Частные выгрузки хранить вне репозитория, задав `AUTOPILOT_COMMERCIAL_DATA_DIR=/absolute/private/directory`. Каталоги `partner`, `costs`, `receipts` внутри штатного data также исключены из Git. Исходные выгрузки с персональными данными или финансовыми реквизитами не добавлять в коммиты и PR.

Каждый источник содержит `fetchedAt` (ISO timestamp с часовым поясом) и `period: {from, to, timeZone: "UTC"}`. Период должен точно совпасть с запросом; фактическая выгрузка должна быть не старше 36 часов и не датирована будущим. Копирование файла не обновляет дату данных. При нескольких аналитических файлах выбирается свежая fetchedAt в запрошенном периоде.

В `analytics/*.json` поля `users`, `offerImpressions`, `productViews`, `formStarts`, `paymentClicks` — неотрицательные целые числа. CTR находится в диапазоне 0–1. `validLeads` принимается только при `confirmation.validLeads` с `source` равным `server-accepted` или `partner-cabinet`, относительным `evidenceRef` и `sha256` сохранённой первичной квитанции. То же правило действует в разрезах по офферу и источнику. События `form-submit-attempt` нельзя переименовывать в validLeads.

Конверсия требует `measurement.<metric>: {unit, cohort, unique: true, complete: true}` у обоих показателей и общий `asOf`. У числителя нужен `subsetOf`, явно содержащий ключ знаменателя: одинаковая аудитория сама по себе не доказывает прохождение предыдущего шага. Допустимы одинаковые уникальные единицы visitors, visits или leads, одинаковые период, аудитория и момент среза; complete означает полную выгрузку наблюдений среза, без выборки и обрезанных строк. Сырые события на посетителя не являются конверсией. Числитель больше знаменателя, отсутствие общего момента среза или несовпадение когорты дают «нет данных».

`partner/attribution.json` дополнительно требует `currency: "RUB"` и `verification: {source: "partner-cabinet", verifiedAt, evidenceRef, sha256}`. EvidenceRef — безопасный относительный путь внутри частного каталога данных; файл первичной выгрузки должен существовать, быть непустым и совпадать с SHA-256. Сверка чисел с первичным отчётом выполняется по реальным данным; метаданные и хеш сами по себе не доказывают достоверность записи партнёра. Счётные поля — целые, денежные — рубли с максимум двумя знаками после запятой.

`paid`/`paidCount` означают оплаченные клиентами счета партнёру. `commission` — начисленная комиссия Этикетки; `payout` — фактически выплаченные проекту деньги. Они выводятся отдельно. Поле JSON `revenue` оставлено для совместимости, но теперь равно projectIncome/commission, а не paid. При отсутствии комиссии доход остаётся неизвестным, даже если оплаты клиентов известны.

`costs/reconciliation.json` содержит такую же дату, период, валюту и первичную квитанцию, но `verification.source: "project-costs"`, `complete: true`, `totalCosts` и `asOf`. Итог netResult считается как комиссия минус сверенные полные затраты только при одинаковом периоде и моменте среза; это результат по начислению, а не денежный поток. Частичные затраты не доказывают прибыль. Отсутствующие данные остаются null/no-data/unverified; подтверждённый ноль остаётся числом 0.

Первичные данные партнёра ещё не собраны: эти проверки готовят корректный отчёт и не подтверждают реальные лиды, оплаты, комиссию или окупаемость.
