# Автопилот контента

Как сайт публикует статьи без участия человека: кто пишет, кто проверяет,
кто выпускает и что делать, когда конвейер встал.

## Зачем это появилось

С 06.07.2026 по 24.08.2026 на сайте не вышло ни одной статьи. Причина
техническая: `auto-publish.yml` умеет только выпускать готовые черновики
(`draft: true → false`), а писать их было некому — `/create-article` запускает
человек. Последний черновик выпустили 06.07.2026, очередь опустела, и
workflow полтора месяца отрабатывал вхолостую с сообщением «No draft articles
left». Никакой сигнализации на этот случай не было.

Автопилот закрывает обе дыры: пополняет очередь черновиков и кричит, когда
она пуста.

## Контур публикации

```
content-autopilot.yml            auto-publish.yml
(1-го числа + понедельник)       (4 раза в день)
        │                                │
        ├─ очередь тем из контент-плана  │
        ├─ research (веб-поиск)          │
        ├─ написание статьи              │
        ├─ шлюз качества + починка       │
        ├─ онлайн-фактчек НПА и цифр     │
        ├─ соцчерновики                  │
        ├─ hero-картинки ПАКЕТОМ         │
        ├─ сборка со страховкой          │
        └─ коммит черновиков в main ─────┤
                                         ├─ берёт черновик с наступившим pubDate
                                         ├─ прогоняет шлюз качества
                                         ├─ снимает draft
                                         └─ коммит → GitHub Pages
```

Черновики пишутся сразу на месяц вперёд, с расстановкой `pubDate` по будним
дням. `auto-publish.yml` каждый день достаёт из очереди ту статью, чья дата
наступила: получается 5 публикаций в неделю без ручного касания.

## Расписание

| Когда | Что |
|---|---|
| 1-го числа, 04:00 МСК | Месячная норма: `QUOTA` статей (по умолчанию 22) на будние дни месяца + пакетный прогон картинок |
| Понедельник, 04:00 МСК | Дозаправка, но только если запас публикаций просел ниже 10 дней |
| Ежедневно 07:00, 11:00, 15:00, 19:00 МСК | Выпуск очередного черновика |

Четыре запуска публикации в день — не четыре статьи в день: за прогон
выпускается максимум один черновик, и только с наступившей `pubDate`. Запас
прогонов нужен, чтобы догнать отставание, если день был пропущен.

## Что происходит с каждой статьёй

1. **Тема.** `scripts/content/lib/content-plan.mjs` парсит кластерные таблицы
   `src/content/wiki/content-plan-2026.md` и вычитает всё, что уже лежит в
   `src/content/blog/`. Порядок: P0 → P1 → P2, внутри приоритета — round-robin
   по категориям, чтобы месяц не состоял из одной маркировки.
2. **Research.** Запрос к модели с веб-поиском: даты, суммы штрафов, номера
   НПА, вопросы читателей. Всё с источниками и `confidence`. Что не
   подтвердилось — попадает в `uncertain` и в статью не идёт.
3. **Написание.** Модель получает фактуру, редполитику и список реальных
   статей для перелинковки. Придумывать факты запрещено промптом, ссылаться
   можно только на переданные slug'и.
4. **Шлюз качества.** `validateArticle()` из `scripts/content/lib/article-rules.mjs`
   проверяет объём, структуру, frontmatter, слова-паразиты, эмодзи, битые
   внутренние ссылки, синтаксис MDX и CPA-врезку. Претензии уходят обратно
   модели — до двух попыток починки.
5. **Онлайн-фактчек.** Второй заход с веб-поиском: существует ли каждый
   упомянутый НПА, верны ли суммы и даты. Несуществующий номер или критичное
   расхождение — обязательная правка. Подтверждённые номера дописываются в
   `src/data/factcheck/auto-verified-npa.json`, результат — в
   `src/data/factcheck/results/<slug>.json` + маркер `.claude/factchecked/<slug>`.
6. **Соцчерновики.** Telegram, VK, Дзен → `src/content/wiki/social/<slug>.md`
   со `status: draft`. Дальше их подхватывает `social-to-docs.yml`.
7. **Картинки.** После генерации всех черновиков — один прогон
   `generate-hero-images.mjs` с `INCLUDE_DRAFTS=1` и `LIMIT=0` на всю месячную
   норму сразу.
8. **Сборка.** `build-guard.mjs` запускает `npm run build`; если сборку роняет
   свежая статья, она уезжает в `.claude/quarantine/`, и сборка повторяется.
   Одна битая статья не съедает месячную норму.

Статья, не прошедшая шлюз после всех попыток, просто не создаётся — тема
остаётся в очереди и попадёт в следующий прогон.

## Шлюз перед публикацией

`auto-publish.yml` не выпускает статью вслепую: каждый черновик перед
снятием `draft` проходит `scripts/content/qa-gate.mjs`.

Блокеры:

- претензии редполитики (те же правила, что и при генерации);
- нет маркера фактчека или он старше 180 дней;
- номер НПА не подтверждён ни whitelist'ом, ни фактчеком;
- скор AI-маркеров ≥ 6/10 (`scripts/check-ai-markers.mjs`).

Не прошедший черновик **не блокирует очередь**: причина пишется в
`.claude/blocked/<slug>`, скрипт берёт следующего кандидата. Заблокированные
статьи видны в `node scripts/content/queue-status.mjs` и в `health-check`.

## Сигнализация

- Пустая очередь роняет прогон `auto-publish.yml` — GitHub присылает письмо о
  падении. Это именно тот сигнал, которого не хватало летом 2026.
- Прогон автопилота, не выпустивший ни одной статьи, тоже падает.
- `node scripts/health-check.mjs` показывает запас публикаций: ≥ 10 дней —
  зелёный, 3–9 — жёлтый, < 3 — красный.
- `node scripts/content/queue-status.mjs` — то же самое одной командой.

## Ручное управление

```bash
# что в очереди и на сколько дней хватит
node scripts/content/queue-status.mjs

# какие темы пойдут в работу следующими
node scripts/content/lib/content-plan.mjs --count=20

# план прогона без обращений к API
DRY_RUN=1 node scripts/content/generate-drafts.mjs

# проверить конкретный черновик тем же шлюзом, что и на публикации
node scripts/content/qa-gate.mjs 2026-09-01-ffd-12-chto-eto
```

Через GitHub Actions:

- **Контент — автопилот** → Run workflow: `count`, `start_date`,
  `skip_images`, `dry_run`.
- **Публикация — автоматический выпуск** → Run workflow: `force_date=1`
  выпускает ближайший черновик, не дожидаясь его `pubDate`.

**Как остановить.** Отключить оба workflow в Actions (кнопка «Disable
workflow»). Черновики останутся в репозитории, ничего не потеряется.

**Как вмешаться в конкретную статью.** Черновик — обычный файл в
`src/content/blog/`. Правьте, коммитьте; выпуск подхватит уже
отредактированный текст. Чтобы отложить статью — сдвиньте `pubDate`.
Чтобы отменить — удалите файл, тема вернётся в очередь.

## Настройки

| Переменная | Где | По умолчанию | Что делает |
|---|---|---|---|
| `QUOTA` | `content-autopilot.yml` | 22 | Потолок статей за месячный прогон |
| `COUNT` | env / input | по будним дням месяца | Сколько статей писать |
| `START_DATE` | env / input | завтра | С какой даты расставлять `pubDate` |
| `CONCURRENCY` | env | 3 | Сколько статей пишется параллельно |
| `DRAFT_MODEL` | env | первый доступный кандидат | Модель OpenRouter |
| `SKIP_FACTCHECK` | env | — | `1` отключает онлайн-фактчек (отладка) |
| `INCLUDE_DRAFTS` | `generate-hero-images.mjs` | — | `1` захватывает черновики в пакетный прогон картинок |
| `FORCE_DATE` | `release-next-draft.mjs` | — | `1` игнорирует `pubDate` |
| `SKIP_GATE` | `release-next-draft.mjs` | — | `1` пропускает шлюз (только отладка) |

Модель не зашита жёстко: `resolveModel()` перебирает `WRITER_CANDIDATES` из
`scripts/content/lib/openrouter.mjs` и берёт первую, которая **реально
отвечает ключу** — проверка идёт пробным запросом, а не наличием модели в
каталоге. Если модель отваливается посреди прогона (сняли версию, изменилась
политика), `chat()` сам переезжает на следующего кандидата.

> **Allowed providers.** У ключа проекта в OpenRouter
> (Settings → Privacy → Allowed providers) разрешены не все провайдеры.
> На 29.08.2026 это `openai`, `deepseek`, `google-ai-studio` — модели
> Anthropic ключу недоступны и стоят в списке кандидатов последними.
> Каталог `/models` эту политику не показывает, поэтому первый прогон
> автопилота упал с `404 No allowed providers`. Расширить список можно на
> https://openrouter.ai/settings/privacy.

## Деньги

Ключ один и уже есть — `OPENROUTER_API_KEY`. Новых секретов автопилоту не
нужно.

На статью приходится 4–6 обращений к модели (research, написание, до двух
починок, фактчек, соцпосты) и одна картинка (~$0.04). Месячная норма в 22
статьи — ориентировочно $15–30 в месяц, точная сумма зависит от выбранной
модели. Следите за балансом OpenRouter: при нуле на счету прогон упадёт с
401/402, и письмо о падении придёт.

## Границы доверия

Автопилот не заменяет редактора там, где цена ошибки высока. Он опирается на
веб-поиск и whitelist НПА, но остаётся генеративной моделью:

- Спорные и резонансные темы (новые законы в день принятия, судебная
  практика) лучше писать через `/create-article` с ручным фактчеком.
- Раз в месяц полезно прочитать `src/content/wiki/autopilot-log.md` и
  выборочно — 2–3 вышедшие статьи.
- `/maintain-content` никто не отменял: автопилот пишет новое, но не следит
  за устареванием старого.

Настройки шлюза сознательно строгие: лучше не выпустить статью, чем
выпустить с выдуманным номером постановления.
