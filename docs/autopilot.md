# Автопилот контента

Как сайт публикует статьи без участия человека: кто пишет, кто проверяет,
кто выпускает и что делать, когда конвейер встал.

## Зачем это появилось

С 06.07.2026 по 29.08.2026 на сайте не вышло ни одной статьи. Причина
техническая: `auto-publish.yml` умеет только выпускать готовые черновики
(`draft: true → false`), а писать их было некому — `/create-article` запускает
человек. Последний черновик выпустили 06.07.2026, очередь опустела, и workflow
полтора месяца отрабатывал вхолостую с сообщением «No draft articles left».
Сигнализации на этот случай не было.

## Кто что делает

| Звено | Кто исполняет | Чем оплачивается |
|---|---|---|
| Вечнозелёные статьи, месячная пачка | **Claude**, Routine «Этикетка — месячная пачка вечнозелёных статей», 1-е число | подписка Claude |
| Ситуативные статьи, до 2 в неделю | **Claude**, Routine «Этикетка — ситуативные статьи и добор очереди», понедельник | подписка Claude |
| Картинки | `content-images-batch.yml` → `generate-hero-images.mjs`, пачкой на все черновики без hero | `OPENROUTER_API_KEY` |
| Выпуск | `auto-publish.yml` → `release-next-draft.mjs` + шлюз качества, по одной статье в будний день | бесплатно |

Обе Routine пишут одинаково: агенты research-specialist → content-writer →
seo-optimizer → social-media-manager, фактчек по первоисточникам, шлюз
`qa-gate.mjs`. Разница только в источнике тем: у месячной это контент-план
(`plan-run.mjs`), у недельной — мониторинг НПА по лентам из
`src/content/wiki/rss-sources.md`.

> **OpenRouter в этом проекте — только для изображений.** Ни один шаг работы
> с текстом не должен ходить в OpenRouter: бюджет ключа рассчитан на hero,
> preview, OG-фоны и иллюстрации флагмана.

## Контур публикации

```
Routine «месячная пачка» (1-е число)        Routine «ситуативные» (понедельник)
        │                                            │
        ├─ plan-run.mjs --json                       ├─ ленты НПА за 14 дней
        │   → месячная норма тем из плана            │   → до 2 тем с датой/суммой
        │                                            ├─ plan-run.mjs → добор до нормы
        └──────────────┬─────────────────────────────┘
                       ▼   по каждой теме, по одной:
        research → write → seo → social
        фактчек по первоисточникам → маркер
        qa-gate.mjs → коммит и пуш этой статьи в main
                       │
                       ▼  (push в src/content/blog/**)
        content-images-batch.yml
        └─ hero на все черновики без картинки, одним прогоном
                       │
                       ▼
        auto-publish.yml (4 раза в день)
        ├─ берёт черновик с наступившим pubDate
        ├─ прогоняет шлюз качества
        ├─ снимает draft
        └─ коммит → GitHub Pages
```

Ключевое правило обеих Routine: **статья коммитится сразу, отдельным
коммитом**. Прогон, упёршийся в лимит на середине списка, оставляет в
репозитории всё, что успел, а недописанные темы сами возвращаются в очередь —
`plan-run.mjs` считает статус по наличию файла, а не по колонке в плане.

## Расписание

| Когда | Что |
|---|---|
| 1-е число, 05:00 МСК | Месячная пачка: вечнозелёные темы из контент-плана на все будние дни месяца |
| Понедельник, 06:00 МСК | Ситуативные статьи по свежим НПА (до 2) плюс добор очереди до месячной нормы (до 5) |
| После каждого пуша черновиков | Пакетная генерация hero на все черновики без картинки |
| Ежедневно 07:00, 11:00, 15:00, 19:00 МСК | Выпуск очередного черновика |
| Ежедневно 00:00 МСК | `hero-backfill-daily.yml` — подстраховка по картинкам, до 10 за прогон |

Четыре запуска публикации в день — не четыре статьи в день: за прогон
выпускается максимум один черновик, и только с наступившей `pubDate`. Запас
прогонов нужен, чтобы догнать отставание, если день был пропущен.

`plan-run.mjs` расставляет `pubDate` только по будним дням, а квота
`QUOTA=22` равна их числу в месяце. Отсюда ритм: одна статья в рабочий день,
выходные пустые.

**Почему месячная пачка, а не 22 статьи в один присест.** Сессия, пишущая
два десятка длинных материалов с research и фактчеком, до конца списка может
и не дойти: кончится контекст или недельный лимит. Поэтому пачка устроена как
поток: тема — фактчек — шлюз — коммит, и так по кругу. Сколько успела, столько
и в репозитории. Недельный прогон в понедельник добирает остаток, так что
очередь восстанавливается сама, без ручного вмешательства.

## План прогона

```bash
node scripts/content/plan-run.mjs              # человекочитаемо
node scripts/content/plan-run.mjs --json       # то, что читает сессия
node scripts/content/plan-run.mjs --count=5 --start=2026-09-01
```

Скрипт не пишет текст. Он готовит задание: берёт незакрытые темы из
`src/content/wiki/content-plan-2026.md` (P0 → P1 → P2, внутри приоритета —
round-robin по категориям, чтобы неделя не состояла из одной маркировки),
расставляет `pubDate` по свободным будним дням, подбирает статьи для
перелинковки и подсказывает известные проекту НПА по категории.

Без `--count` очередь добивается до месячной нормы: по одной статье на каждый
оставшийся будний день месяца, не больше `QUOTA` (22), минус уже
запланированное. Очередь закрыта — скрипт честно говорит, что писать нечего.

## Промпт Routine

Две Routine на claude.ai/code/routines — там же кнопки «запустить сейчас»,
«выключить» и правка промпта:

| Routine | id | Расписание |
|---|---|---|
| Этикетка — месячная пачка вечнозелёных статей | `trig_01SMV5eXNW3hnrcSC1ZC2Ryt` | `0 2 1 * *` (1-е число, 05:00 МСК) |
| Этикетка — ситуативные статьи и добор очереди | `trig_013pPZoEE2yV6nLPgYWwZ5qZ` | `0 3 * * 1` (понедельник, 06:00 МСК) |

Промпты у них разные только в источнике тем и в объёме; всё остальное —
клонирование, фактчек, шлюз, покоммитная выдача — одинаковое. Ниже приведён
промпт месячной пачки; недельный отличается первой частью (мониторинг НПА
вместо контент-плана) и потолком в 2 ситуативные темы плюс 5 на добор.

**Почему промпт начинается с клонирования.** Прогоны 31.08 и 04.09.2026
завершились статусом «успех», отработав десятками минут и потратив 11 $ и
39 $ соответственно, но не оставили в репозитории ни одного файла. Причину
нашла диагностическая сессия 04.09: **Routine стартует в пустом каталоге,
рабочей копии репозитория в среде нет**. Репозиторий числится в источниках
окружения, но в рабочий каталог сессии он не разворачивается, а
`update_trigger` умеет менять только текст задания — поэтому клонирование
вынесено в шаг 0 самого промпта. Без него первая же команда (`node scripts/content/plan-run.mjs`)
не находит скриптов, и прогон уходит в никуда.

Проверено в среде `env_01Y9bC1GR6r8J87kbPnMLQCA` 04.09.2026: `git clone` и
`git push` работают, node v22.22.2, `npm install` для `plan-run.mjs` и
`qa-gate.mjs` не нужен, `npm run build` зависимости требует.

Каждый прогон стартует свежую сессию, поэтому промпт самодостаточный:

```
Ты — редактор медиа «Этикетка» (etiketka-media.ru), репозиторий
burbonivanovich-oss/ts_piot. Задача прогона — пополнить очередь
черновиков на ближайшую неделю.

0. РАБОЧАЯ КОПИЯ. Сессия стартует в пустом каталоге: репозитория на диске
   нет, и без этого шага ни одна команда ниже не сработает. Первым делом:

   git clone https://github.com/burbonivanovich-oss/ts_piot /home/user/ts_piot
   cd /home/user/ts_piot

   Все дальнейшие команды выполняй из /home/user/ts_piot, работай на ветке
   main. Клонируй полностью, без --depth: shallow-копия мешает rebase при
   пуше. Если клонирование не прошло — остановись и напиши точный текст
   ошибки, ничего больше не предпринимая.

ГЛАВНОЕ ПРАВИЛО ПРОГОНА: этот прогон не имеет права закончиться молча.
Что бы ни случилось, ты обязан дописать итог в
src/content/wiki/autopilot-log.md, закоммитить и запушить в main, а в
финальном сообщении назвать числа. Ноль написанных статей — нормальный
исход, если он объяснён в журнале; ноль статей без объяснения — провал
прогона.

1. Возьми задание: node scripts/content/plan-run.mjs --count=5 --json
   Пустой items — очередь закрыта: запиши это в журнал, закоммить и
   заверши сессию.

2. По каждому элементу плана напиши статью агентами проекта:
   research-specialist → content-writer → seo-optimizer →
   social-media-manager. Правила — docs/content-rules.md. Из плана бери
   slug, pubDate, reviewDate, title, keyword, category, cpa. Ставь
   draft: true. Внутренние ссылки — минимум 3 и только из linkCandidates
   этой темы. Номера НПА — только из npaHints либо подтверждённые через
   WebSearch по первоисточнику. Факта нет — не пиши его.
   Статья: src/content/blog/<slug>.mdx
   Соцчерновик: src/content/wiki/social/<slug>.md

3. ФАКТЧЕК ДО ШЛЮЗА, а не после. Шлюз требует маркер
   .claude/factchecked/<slug>, и поставить его — отдельная работа:
   node scripts/factcheck/extract-claims.mjs <slug>, сверка дат, сумм
   штрафов и номеров НПА с первоисточниками через WebFetch, запись в
   src/data/factcheck/results/<slug>.json, и только потом маркер с датой
   проверки внутри. Не сверил — маркер не ставь и статью не выпускай.

4. Каждую статью прогони через node scripts/content/qa-gate.mjs <slug>
   Красный шлюз — правь, максимум две попытки. Не вышло — удали файлы и
   переходи к следующей теме. Обязательно запиши в журнал, какая тема и
   по какой причине отвалилась (дословно первый блокер шлюза).

5. npm run build — красная сборка чинится, либо виновная статья
   убирается. Если build требует зависимостей, выполни npm install.

6. Допиши итог прогона в src/content/wiki/autopilot-log.md: дата, сколько
   тем взято, сколько доехало, что отвалилось и почему, сколько
   черновиков в очереди (node scripts/content/queue-status.mjs).
   Закоммить и запушь в main. Пуш не проходит — git pull --rebase origin
   main и повтори, иначе точный текст ошибки в отчёт.
   Картинки не трогай: их сгенерит workflow «Картинки — пакетный прогон».

ВАЖНО: OpenRouter в этом проекте — только для изображений.

7. В конце отчёт: сколько написано, сколько отвалилось и почему, что
   лежит в очереди. Контур целиком — docs/autopilot.md.
```

## Шлюз перед публикацией

`auto-publish.yml` не выпускает статью вслепую: каждый черновик перед снятием
`draft` проходит `scripts/content/qa-gate.mjs`.

Блокеры:

- претензии редполитики — `scripts/content/lib/article-rules.mjs`: объём,
  структура, frontmatter, слова-паразиты, эмодзи, битые внутренние ссылки,
  синтаксис MDX, CPA-врезка;
- нет маркера фактчека или он старше 180 дней;
- номер НПА не подтверждён ни whitelist'ом, ни фактчеком;
- скор AI-маркеров ≥ 6/10 (`scripts/check-ai-markers.mjs`).

Не прошедший черновик **не блокирует очередь**: причина пишется в
`.claude/blocked/<slug>`, скрипт берёт следующего кандидата. Заблокированные
статьи видны в `node scripts/content/queue-status.mjs` и в `health-check`.

## Сигнализация

- Пустая очередь роняет **первый за сутки** прогон `auto-publish.yml`
  (07:00 МСК) — GitHub присылает письмо. Это именно тот сигнал, которого не
  хватало летом 2026. Остальные три прогона в сутки молчат, чтобы одна
  проблема не слала четыре письма.
- `node scripts/health-check.mjs` показывает запас публикаций: ≥ 10 дней —
  зелёный, 3–9 — жёлтый, < 3 — красный.
- `node scripts/content/queue-status.mjs` — то же самое одной командой.

## Ручное управление

```bash
node scripts/content/queue-status.mjs          # что в очереди и на сколько хватит
node scripts/content/plan-run.mjs              # какие темы пойдут следующими
node scripts/content/qa-gate.mjs <slug>        # проверить черновик шлюзом публикации
node scripts/content/lib/content-plan.mjs      # остаток тем в контент-плане
```

Через GitHub Actions:

- **Картинки — пакетный прогон** → Run workflow: `force`, `limit`.
- **Публикация — автоматический выпуск** → Run workflow: `force_date=1`
  выпускает ближайший черновик, не дожидаясь его `pubDate`.

Routine: claude.ai/code/routines — там же кнопка запуска вне расписания.
Обе безопасно запускать повторно: `plan-run.mjs` не выдаст тему, по которой
файл уже есть, поэтому дублей не будет.

**Как остановить.** Выключить обе Routine на claude.ai/code/routines и, если
нужно, `auto-publish.yml` в Actions. Черновики останутся в репозитории.
Выключение только выпуска останавливает сайт, но не производство: очередь
продолжит расти.

**Как вмешаться в статью.** Черновик — обычный файл в `src/content/blog/`.
Правьте и коммитьте, выпуск подхватит отредактированный текст. Отложить —
сдвиньте `pubDate`. Отменить — удалите файл, тема вернётся в очередь.

## Настройки

| Переменная | Где | По умолчанию | Что делает |
|---|---|---|---|
| `QUOTA` | env для `plan-run.mjs` | 22 | Месячный потолок статей |
| `--count` | флаг `plan-run.mjs` | норма месяца минус запланированное | Сколько тем в задание |
| `--start` | флаг `plan-run.mjs` | завтра | С какой даты расставлять `pubDate` |
| `INCLUDE_DRAFTS` | `generate-hero-images.mjs` | — | `1` захватывает черновики в пакетный прогон |
| `FORCE_DATE` | `release-next-draft.mjs` | — | `1` игнорирует `pubDate` |
| `SKIP_GATE` | `release-next-draft.mjs` | — | `1` пропускает шлюз (только отладка) |

## Границы доверия

Автопилот не заменяет редактора там, где цена ошибки высока:

- резонансные темы (новый закон в день принятия, судебная практика) лучше
  писать вручную через `/create-article` с ручным фактчеком;
- раз в месяц полезно выборочно прочитать 2–3 вышедшие статьи;
- `/maintain-content` никто не отменял: автопилот пишет новое, но не следит
  за устареванием старого.

Настройки шлюза сознательно строгие: лучше не выпустить статью, чем выпустить
с выдуманным номером постановления.
