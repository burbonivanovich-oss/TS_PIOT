# Редакционный цикл: автоматика с человеком в контуре

Три рутины Claude ведут контент от плана до выпуска, а редактор-человек
согласовывает план и вычитывает статьи. Между запусками рутины ничего не
помнят — всё состояние лежит в репозитории.

## Схема

```
      ┌─ Рутина A ─ /cycle-plan ────────── 1-е число месяца, 09:00 МСК
      │  Собирает 12 тем → GitHub Issue → уведомление
      │  Контент-план в репозитории НЕ трогает
      ▼
  awaiting_review ◄─────────────────┐
      │                             │ правки применены,
      │ редактор пишет в Issue      │ ждём дальше
      ▼                             │
  ┌─ Рутина B ─ /cycle-listen ──────┴──── каждые 4 часа, будни
  │  Читает комментарии, применяет правки, ловит «одобряю»
  │  Нет нового → выходит молча
  ▼
  approved  ── план записан в content-plan-2026.md
      │
      ▼
  ┌─ Рутина C ─ /cycle-batch ──────────── понедельник, 08:00 МСК
  │  Берёт 3 темы по приоритету → /create-article ×3 → один PR
  │  ЗАБЛОКИРОВАНА, пока прошлый батч не влит
  ▼
  batch_review
      │
      │ редактор вычитывает PR
      ▼
  Рутина B разбирает замечания → правки в тредах
      │
      │ редактор мержит PR
      ▼
  approved (остались темы) ──► следующий батч
  done     (темы кончились) ──► ждём рутину A
```

## Почему так

**Состояние в файле, а не в сессии.** Рутина каждый раз стартует с чистого
листа. `src/data/editorial-cycle.json` — единственный источник правды о том,
на каком этапе цикл. Меняется только через `scripts/cycle-state.mjs`, чтобы
модель не разъехалась со схемой.

**План не пишется в репозиторий до одобрения.** Пока редактор не сказал
«одобряю», `content-plan-2026.md` не меняется. Иначе автоматика засоряет
план темами, которые человек ещё не видел.

**Батч из 3 статей с предохранителем.** Прямое требование: не утонуть в
правках. `can-start-batch` возвращает ненулевой код, пока предыдущий PR
не влит, — рутина C физически не может запустить второй батч.

**Молчание по умолчанию.** Рутина B срабатывает ~20 раз в неделю. Уведомление
приходит только когда она реально что-то сделала.

## Состояния

| Состояние | Что значит | Кто двигает дальше |
|---|---|---|
| `idle` | Активного цикла нет | Рутина A |
| `awaiting_review` | План у редактора в Issue | Редактор → рутина B |
| `approved` | План одобрен, записан в репозиторий | Рутина C |
| `batch_review` | Батч статей в PR | Редактор → рутина B |
| `done` | Все темы цикла выпущены | Рутина A (новый цикл) |

## CLI состояния

```bash
node scripts/cycle-state.mjs get              # человекочитаемая сводка
node scripts/cycle-state.mjs get --json       # полное состояние

node scripts/cycle-state.mjs init --cycle 2026-08 --issue 42 \
    --plan /tmp/plan.json --editors <логин> --batch-size 3

node scripts/cycle-state.mjs set-state approved
node scripts/cycle-state.mjs seen-comment 1234567
node scripts/cycle-state.mjs can-start-batch  # exit 0 = можно, 1 = нельзя
node scripts/cycle-state.mjs next-batch --size 3
node scripts/cycle-state.mjs add-batch --slugs a,b,c --pr 51
node scripts/cycle-state.mjs close-batch --pr 51

node scripts/cycle-state.mjs add-topic --slug x --title "..." --priority P1
node scripts/cycle-state.mjs drop-topic x
node scripts/cycle-state.mjs reset --force    # аварийный сброс
```

Встроенные предохранители:

- `init` не запустится поверх идущего цикла;
- `add-batch` не примет тему, которая уже написана или на ревью;
- `seen-comment` не откатывает счётчик назад;
- `can-start-batch` — единственный гейт запуска батча.

## Интерфейс редактора

Редактор работает в GitHub Issue. Аккаунт с доступом к репозиторию — всё,
что нужно; уведомления на почту GitHub шлёт сам.

**По плану:**

| Что написать | Что произойдёт |
|---|---|
| `одобряю` | План уходит в репозиторий, стартует первый батч |
| `убрать 3, 7` | Темы 3 и 7 снимаются |
| `добавить: как выбрать ОФД для общепита` | Тема добавляется (P1) |
| `4 → P0` | Приоритет темы 4 повышается |
| `2: переформулировать на "..."` | Меняется заголовок и целевой запрос |
| `отклоняю, причина` | Цикл закрывается, план пересобирается |

Правки можно слать сколько угодно раз. Каждая пачка — ответ рутины B
с перечнем применённого и обновлённой таблицей.

**По статьям:** обычные комментарии к строкам в PR. Рутина B правит и
отвечает в тредах. Мерж PR = приёмка батча.

Непонятную формулировку рутина не угадывает — переспрашивает.

## Как поставить рутины на расписание

Расписание задаётся в UTC, МСК = UTC+3.

**Рутина A — планировщик.** 1-е число, 09:00 МСК:

```
create_trigger(
  name: "Контур A — контент-план",
  cron_expression: "0 6 1 * *",
  create_new_session_on_fire: true,
  environment_id: "env_01Y9bC1GR6r8J87kbPnMLQCA",
  notifications: { push: true, email: true },
  prompt: "Выполни /cycle-plan. Работай в репозитории burbonivanovich-oss/TS_PIOT,
           ветка main. Следуй .claude/commands/cycle-plan.md дословно."
)
```

**Рутина B — слушатель.** Каждые 4 часа по будням:

```
create_trigger(
  name: "Контур B — ответы редактора",
  cron_expression: "0 5,9,13,17 * * 1-5",
  create_new_session_on_fire: true,
  environment_id: "env_01Y9bC1GR6r8J87kbPnMLQCA",
  notifications: { push: true },
  prompt: "Выполни /cycle-listen. Репозиторий burbonivanovich-oss/TS_PIOT, ветка main.
           Следуй .claude/commands/cycle-listen.md. Если новых комментариев нет —
           заверши работу молча, без уведомления."
)
```

**Рутина C — батч.** Понедельник, 08:00 МСК:

```
create_trigger(
  name: "Контур C — батч статей",
  cron_expression: "0 5 * * 1",
  create_new_session_on_fire: true,
  environment_id: "env_01Y9bC1GR6r8J87kbPnMLQCA",
  notifications: { push: true, email: true },
  prompt: "Выполни /cycle-batch. Репозиторий burbonivanovich-oss/TS_PIOT, ветка main.
           Следуй .claude/commands/cycle-batch.md. Сначала обязательно проверь
           can-start-batch — при ненулевом коде заверши работу молча."
)
```

Управление: `list_triggers`, `update_trigger`, `delete_trigger`,
`fire_trigger` (запуск вне расписания — удобно для обкатки).

## Обкатка перед автоматикой

Прогнать цикл руками, по одной команде за раз:

1. `/cycle-plan` — посмотреть, как выглядит Issue глазами редактора.
2. Оставить в Issue тестовый комментарий с правками.
3. `/cycle-listen` — проверить, что правка распозналась и ответ вменяемый.
4. Написать `одобряю`, снова `/cycle-listen` — план должен уехать в репозиторий.
5. `/cycle-batch` — дождаться PR с тремя статьями.
6. Влить PR, `/cycle-listen` — батч должен закрыться, состояние вернуться
   в `approved`.

После этого ставить рутины на расписание.

## Что может пойти не так

| Симптом | Причина | Что делать |
|---|---|---|
| Рутина C молчит неделями | Открытый PR не влит | Влить или закрыть PR, затем `/cycle-listen` |
| Рутина B отвечает на старое | `seen-comment` не закоммитился | Проверить `git log src/data/editorial-cycle.json`, выставить счётчик вручную |
| Два Issue с планом | `init` прошёл при незакрытом цикле | Закрыть лишний Issue, `reset --force`, пересобрать |
| Состояние разъехалось с GitHub | Рутина упала между действием и коммитом | `get --json`, сверить с Issue/PR, поправить через CLI |
| Батч собрал 1 статью из 3 | Не хватило бюджета сессии или шлюзы | Норма: остальные темы остались `pending` |

Аварийный выход из любого состояния — `reset --force`, затем `/cycle-plan`
заново. Написанные статьи при этом не теряются: они уже в git.
