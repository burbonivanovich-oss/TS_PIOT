# /auto-day — суточный проход

Единственная рутина, которую нужно ставить на расписание. Всё остальное она
вызывает сама. Работает без согласований: решения принимают гейты, человек в
цикле не участвует и о проходе узнаёт из отчёта, а не в момент прохода.

**Молчание по умолчанию.** Если делать нечего (нормы месяца выполнены,
свободных слотов нет) — заверши работу без уведомления.

## 1. Наряды

```bash
node autopilot/scripts/pipeline.mjs plan --json
```

Скрипт сам пополнит бэклог, пересчитает очередь рерайтов, посчитает норму дня
с учётом долга и займёт слоты. Если `orders` пуст — заверши проход молча.

Разбор полей наряда:

| Поле | Что означает |
|---|---|
| `kind` | `new` — писать с нуля, `rewrite` — переписывать существующую |
| `slug` | Имя файла без расширения. **Не менять**: по нему идёт учёт |
| `title` | Рабочий заголовок из шаблона. Финальный формулируешь сам |
| `keywords` | Целевые запросы. Должны попасть в title/description/H2 |
| `dedupe.verdict` | `warn` — обязательно сузить угол и сослаться на соседа |
| `dedupe.related` | Статьи, с которыми нельзя пересекаться по смыслу |

## 2. Написание

По каждому наряду выполни соответствующую процедуру:

- `kind: new` → `.agents/skills/auto-write/SKILL.md`
- `kind: rewrite` → `.agents/skills/auto-rewrite/SKILL.md`

По умолчанию обрабатывай наряды последовательно: так проще контролировать
факты, загрузку источников и состояние корпуса, а контекст не дублируется.
Параллелить можно только несколько независимых нарядов, когда это действительно
сокращает время и есть отдельная проверка каждого результата перед приёмкой.
Не создавай субагента ради одного обычного наряда.

Наряд, по которому субагент не смог довести текст до прохождения гейтов,
оставляй как есть: приёмка сама разберётся, это не повод чинить руками.

## 3. Приёмка

```bash
node autopilot/scripts/pipeline.mjs settle
```

Что делает: прогоняет гейты и проверку на дубль по каждому наряду, публикует
прошедшее (`draft: false`), заворачивает непрошедшее, после второй неудачи
отправляет тему в карантин, затем раскладывает перелинковку по всему корпусу
и закрывает счётчики месяца.

**Результат приёмки не оспаривается.** Если гейт завернул текст — это ответ, а
не повод переспорить проверку правкой порогов. Пороги меняются отдельным
решением в `autopilot/config/autopilot.config.json`, а не по ходу прохода.

## 4. Коммит

```bash
git -C <contentRoot> add src/content/blog
git -C <contentRoot> commit -m "автопилот: <N> статей, <M> рерайтов, <K> ссылок"
git -C <contentRoot> push
```

Коммить только `src/content/blog`. Служебные файлы автопилота (`data/`) живут в
своём репозитории и коммитятся отдельно.

## 5. Отчёт

Одним сообщением, коротко:

```
2026-08-10: опубликовано 5 (+2 рерайта), заврачено 1, в карантине 0
Месяц: 43/200. Ссылок вставлено 12, сирот осталось 19.
```

Уведомление отправляй, только если есть что сообщить: непустой проход,
карантин пополнился, или норма месяца недостижима при текущем темпе.

## Когда останавливаться и звать человека

Автономность не означает «молчать при поломке». Останови проход и сообщи, если:

- `pipeline.mjs plan` падает — сломан конфиг или недоступен контент-репозиторий;
- в карантине больше 10 тем — гейт настроен так, что через него не проходит
  ничего, и контур молотит вхолостую;
- бэклог не пополняется (`refill` добавил 0 при непустой потребности) — темы
  кончились, нужны новые сущности в `autopilot/data/seeds.json`;
- дневная норма не выбирается третий проход подряд.
