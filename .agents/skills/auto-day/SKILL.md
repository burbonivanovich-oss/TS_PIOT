# /auto-day

Единственный владелец производства и выпуска. Цели: 55 новых статей и 14
обновлений за месяц, максимум 3 материала за проход. Согласований внутри
прохода нет. Источник норм и порогов — autopilot/config/autopilot.config.json.

## Полный проход

Работать из корня принимающего репозитория сайта на чистой main.
Не подменять checkout, не выполнять fetch/pull с перезаписью грязных файлов,
не менять ветку текущего незавершённого прохода. Перед первым запуском должны
быть установлены зависимости сайта по lockfile (`npm ci`) и доступен
авторизованный Codex CLI. Движок не требует установки зависимостей.

```bash
AUTOPILOT_PREFLIGHT_GIT=1 AUTOPILOT_ALLOWED_BRANCH=main \
AUTOPILOT_ALLOWED_PATHS=autopilot/data,autopilot/research,src/content/blog,public/images/hero,public/images/preview,.claude/factchecked,src/data/factcheck/results,src/data/factcheck/claims \
node autopilot/scripts/daily.mjs --commit --push --remote origin --target-ref refs/heads/main
```

`daily.mjs` сам восстанавливает прерванный проход, выполняет preflight и
полную проверку тестов до новых мутаций, проверяет первоисточники, планирует,
вызывает auto-write/auto-rewrite по текущим нарядам, принимает, строит сайт,
фиксирует контент вместе с состоянием и проверяет push. Не запускать plan,
writer, checkpoint, settle или ручной git add/commit поверх работающего daily.
Не запускать вторую модель для файла, на который уже есть квитанция доставки.

Если journal требует продолжения commit/push, повторить ту же команду и
назначение: новый план не должен обгонять незавершённую доставку. Живой
модельный процесс нельзя считать умершим по отсутствию свежего вывода.
Не удалять lock/journal, не править код, корпус или метаданные в активном
checkout, пока владелец не завершился и его процессная группа не остановлена.
Пороги не ослаблять ради темпа. Отказ гейтов — окончательный результат
текущей попытки; повторный отказ отправляет тему в карантин.

## Проверка публикации

`draft: false`, зелёная сборка и push ещё не подтверждают публикацию.
После успешного push дождаться завершения деплоя, затем проверить
`/release.json` и страницы выпущенного прохода командой. Ожидаемый SHA —
`result.delivery.publication.commit` для обычного прохода или
`result.publication.commit` для восстановления push. Это фактически
отправленный и проверенный remote SHA. После объединения Wordstat он
отличается от исходного `metadataCommit`, который остаётся квитанцией.
Без подтверждённого push SHA проверку публикации не считать выполненной:

```bash
node autopilot/scripts/live-release.mjs --site https://etiketka-media.ru \
  --commit <pushedCommit> --pages /absolute/path/pages.json
```

Аргумент --pages — путь к JSON-файлу вне рабочего checkout. Формат массива страниц и обязательного текста посмотреть в
`autopilot/scripts/live-release.mjs`; включить фактически выпущенные URL.
Версия сайта должна совпасть с ожидаемым SHA и sourceClean должен быть true.
Не помечать deployed=true до этой проверки. Не отправлять тестовые заявки.

## Расписание и сообщения

Одна локальная автоматизация Codex вызывает эту процедуру раз в день.
Прежние пишущие Routine и cron выпуска должны быть выключены до включения
нового владельца. GitHub autopilot.yml остаётся ручным, auto-publish.yml
теперь только читает очередь. Не создавать второе расписание для plan/settle.

Если нет работы и состояние не изменилось — завершить без уведомления.
Сообщать о фактическом выпуске, новых записях карантина, сбое, расхождении
версии сайта либо необходимости действия пользователя. В отчёте разделять
приёмку, push и доступность на сайте, NEW и REWRITE. Остановиться при красных
тестах, повреждённом конфиге, невозможности безопасного восстановления,
карантине больше 10 или недостижимости нормы третий проход подряд.

## Дополнительный проход подтверждённых исправлений

Для внепланового исправления добавить к той же команде daily
`--corrections-only`. Этот режим выдаёт только доступные наряды с
подтверждёнными ошибками, в пределах свободных слотов и оставшейся месячной
нормы рерайтов. Восстановление уже начатого прохода и выпуск годного
содержимого очереди сохраняют приоритет. Без ошибки новая модель не вызывается.
Подтверждённое исправление выходит без ожидания месячного календаря;
гейты, сборка, дневной потолок и проверка push/deploy остаются обязательными. Единственный ежедневный scheduler использует обычный полный
режим; второе расписание для исправлений не создавать.
