# /auto-write — статья по наряду

Вход: один наряд `kind: new` из `autopilot/data/orders.json`. Выход: файл
`<contentRoot>/src/content/blog/<slug>.md`, проходящий гейты.

Никаких согласований. Никаких вопросов «а стоит ли писать эту тему» — решение
уже принято планировщиком и проверкой дублей. Твоя задача — текст.

## 0. Прочитай наряд

```bash
node -e "const o=require('./autopilot/data/orders.json');console.log(JSON.stringify(o.orders.find(x=>x.slug==='$1'),null,2))"
```

Если `dedupe.verdict === 'warn'` — прочитай статьи из `dedupe.related` целиком,
прежде чем писать. Твой текст обязан отвечать на другой вопрос, чем они, и
ссылаться на них там, где читатель захочет подробностей. Пересказ соседа —
брак, который приёмка поймает проверкой совпадения тела.

## 1. Ресёрч

Собери фактуру по целевым запросам наряда. Требования к источникам:

- **Только первоисточники** для дат, сумм и норм: `publication.pravo.gov.ru`,
  `consultant.ru`, `garant.ru`, `nalog.gov.ru`, `честныйзнак.рф`, `crpt.ru`.
  Вторичные пересказы (блоги, агрегаторы) — не источник, даже если удобнее.
- **Каждая дата, сумма штрафа и ссылка на норму — с подтверждением.** Гейт
  `sources` считает такие утверждения и требует ссылки; но важнее, что
  проверять текст после публикации будет некому.
- Если факт не подтверждается — **не пиши его**. Не «вероятно», не «по данным
  экспертов». Убери утверждение или сузь формулировку до проверяемой.

Черновик фактуры сохрани в `autopilot/research/<slug>.md` — он нужен рерайту
через полгода, чтобы не собирать то же самое заново.

## 2. Текст

Структура: лид без воды → 4–7 разделов H2 → короткий вывод с действием.

Обязательное:

- **Объём** 4000–22000 символов тела (норма гейта). Реальная цель — 6000–9000.
- **H2 ≥ 3**, в двух-трёх из них — целевые запросы наряда в естественной форме.
- **description** 100–200 символов, с целевым запросом, без кликбейта.
- **3–8 внутренних ссылок** на существующие статьи корпуса, с осмысленными
  якорями. Якорь — фраза, по которой понятно, куда ведёт: «поэкземплярный
  учёт», а не «здесь» и не «подробнее».
- **Ссылки только на существующие slug'и.** Проверь:
  `ls <contentRoot>/src/content/blog | grep <фрагмент>`. Гейт `links-valid`
  заворачивает битые ссылки как блокер.

Запрещённое (гейт `ai-markers` ловит, но список неполный — думай сам):
«в современном мире», «стоит отметить», «таким образом», «в заключение»,
«широкий спектр», «на сегодняшний день», «давайте разберёмся».

Пиши так, как объясняют коллеге: конкретика, цифры, что делать. Абзац без
факта или действия — лишний абзац.

## 3. Frontmatter

```yaml
---
title: "<финальный заголовок, до 65 символов>"
description: "<100–200 символов>"
pubDate: "<сегодня, YYYY-MM-DD>"
tags:
  - <3–6 тегов из существующих в корпусе>
categories:
  - <одна категория из корпуса>
draft: true
seo:
  keywords:
    - <целевые запросы наряда>
---
```

`draft: true` ставится всегда: снимет его приёмка, если гейты пройдены.
Дата в имени файла и `pubDate` должны совпадать.

## 4. Самопроверка (обязательно, до завершения)

```bash
node autopilot/scripts/gates.mjs check --slug <slug>
```

Не прошло — **чини и прогоняй снова**, до трёх заходов. Читай `detail` каждой
проверки: там написано, чего именно не хватает. Самые частые причины отказа:

| Проверка | Что делать |
|---|---|
| `sources` | Добавить ссылки на первоисточники к датам и суммам, либо убрать неподтверждённые утверждения |
| `interlink` | Добавить внутренних ссылок до 3–8 |
| `links-valid` | Исправить slug'и: ссылки ведут на несуществующие статьи |
| `length` | Дописать по существу, а не разбавить водой |
| `ai-markers` | Переписать абзацы со штампами |
| `duplication` | Сузить угол: текст пересказывает существующую статью |

После трёх неудачных заходов остановись и оставь файл как есть — приёмка
отправит тему на второй круг или в карантин. Это нормальный исход, а не повод
подгонять текст под проверку.
