# /auto-write — статья по наряду

Вход: один наряд `kind: new` из `autopilot/data/orders.json`. Выход: файл
`<contentRoot>/src/content/blog/<slug>.mdx`, проходящий гейты сайта.
В наряде может оставаться подсказка target с `.md`: сохраняй тот же slug,
но используй MDX, чтобы компоненты Astro действительно отрендерились.

Никаких согласований. Никаких вопросов «а стоит ли писать эту тему» — решение
уже принято планировщиком и проверкой дублей. Твоя задача — текст.

## 0. Прочитай наряд

```bash
node -e "const o=require('./autopilot/data/orders.json');console.log(JSON.stringify(o.orders.find(x=>x.slug==='$1'),null,2))"
```

Если `dedupe.verdict === 'warn'` — прочитай статьи из `dedupe.related` целиком,
прежде чем писать. Твой текст обязан отвечать на другой вопрос, чем они, и
ссылаться на них там, где читатель захочет подробностей. Пересказ соседа —
брак, который приёмка поймает проверкой совпадения тела.

## 1. Ресёрч

Собери фактуру по целевым запросам наряда. Требования к источникам:

- **Только первоисточники** для дат, сумм и норм: `publication.pravo.gov.ru`,
  `consultant.ru`, `garant.ru`, `nalog.gov.ru`, `честныйзнак.рф`, `crpt.ru`.
  Вторичные пересказы (блоги, агрегаторы) — не источник, даже если удобнее.
- **Каждая дата, сумма штрафа и ссылка на норму — с подтверждением.** Гейт
  `sources` считает такие утверждения и требует ссылки; но важнее, что
  проверять текст после публикации будет некому.
- Если факт не подтверждается — **не пиши его**. Не «вероятно», не «по данным
  экспертов». Убери утверждение или сузь формулировку до проверяемой.

Для каждого критического утверждения сохрани содержательную сверку по
[контракту evidence](../../../autopilot/docs/claim-evidence.md) в
`autopilot/data/claim-evidence/<slug>.json`. Получи реальный снимок источника
через `node autopilot/scripts/source-snapshot.mjs --url <URL>`, прочитай документ
и сверь дату, сумму, область применения и актуальность нормы. Источник с HTTP
200 ещё не подтверждает утверждение. Не выдумывай текст снимка и не ставь
`verified` до смысловой сверки. Дату/сумму, которую не смог подтвердить, удали.
Дополнительно выполняй фактчек сайта и сохраняй результаты/маркер только
после проверки; QA сайта — обязательный блокер в гейтах движка.

Черновик фактуры сохрани в `autopilot/research/<slug>.md` — он нужен рерайту
через полгода, чтобы не собирать то же самое заново.

Это единственный разрешённый файл research для наряда. Вывод самопроверок
печатай в терминал, дополнительные `*-checks.json`, логи и вспомогательные
скрипты не сохраняй. Их появление откатит всю доставку как постороннюю правку.

## 2. Текст

Структура: лид без воды → 4–7 разделов H2 → короткий вывод с действием.

Обязательное:

- **Объём** 4000–22000 символов тела (норма гейта). Реальная цель — 6000–9000.
- **H2 ≥ 4**, включая секцию «## Частые вопросы» минимум с тремя вопросами H3;, в двух-трёх из них — целевые запросы наряда в естественной форме.
- **description** 140–160 символов, с целевым запросом, без кликбейта.
- **3–8 внутренних ссылок** на существующие статьи корпуса, с осмысленными
  якорями. Якорь — фраза, по которой понятно, куда ведёт: «поэкземплярный
  учёт», а не «здесь» и не «подробнее».
- **Ссылки только на существующие slug'и.** Проверь:
  `ls <contentRoot>/src/content/blog | grep <фрагмент>`. Гейт `links-valid`
  заворачивает битые ссылки как блокер.

Запрещённое (гейт `ai-markers` ловит, но список неполный — думай сам):
«в современном мире», «стоит отметить», «таким образом», «в заключение»,
«широкий спектр», «на сегодняшний день», «давайте разберёмся».

Пиши так, как объясняют коллеге: конкретика, цифры, что делать. Абзац без
факта или действия — лишний абзац.

### Контракт принимающего сайта до первой самопроверки

- Используй MDX и импорт `import CpaCallout from '../../components/CpaCallout.astro';` после frontmatter. Вставь ровно один `<CpaCallout id="..." />` из существующего реестра `src/data/cpa-banners.ts`. Выбери блок по теме и сверь его обещания; не редактируй общий реестр во время написания статьи.
- Сайт требует минимум 900 слов, четыре H2 и три вопроса FAQ с H3, 4–7 тегов в нижнем регистре. Проверяй требования сайта вместе с гейтами движка.
- После содержательной проверки сохрани `.claude/factchecked/<slug>` как JSON с `passed: true`, `checkedAt: new Date().toISOString()` и конкретным scope проверки. Если в тексте есть НПА, добавь результат в `src/data/factcheck/results/<slug>.json`; для федерального закона используется `kind: "fz"`. Пустые подтверждения не заменяют выполненную проверку, дата файла её не доказывает.
- Новые hero/preview-файлы называй `<slug>.<ext>` или `<slug>-<суффикс>.<ext>`. Можно использовать подходящий существующий файл после визуальной проверки. Состояние и квитанции изменяет родительский исполнитель.

## 3. Frontmatter

```yaml
---
title: "<финальный заголовок, до 65 символов>"
description: "<100–200 символов>"
pubDate: "<сегодня, YYYY-MM-DD>"
tags:
  - <4–6 тегов из существующих в корпусе>
categories:
  - <одна категория из корпуса>
draft: true
autopilotHold: true
seo:
  keywords:
    - <целевые запросы наряда>
---
```

`draft: true` и `autopilotHold: true` ставятся всегда: снимет его приёмка, если гейты пройдены.
Дата в имени файла и `pubDate` должны совпадать.

## 4. Самопроверка (обязательно, до завершения)

```bash
node autopilot/scripts/gates.mjs check --slug <slug>
```

Не прошло — **чини и прогоняй снова**, до трёх заходов. Читай `detail` каждой
проверки: там написано, чего именно не хватает. Самые частые причины отказа:

| Проверка | Что делать |
|---|---|
| `sources` | Добавить ссылки на первоисточники к датам и суммам, либо убрать неподтверждённые утверждения |
| `interlink` | Добавить внутренних ссылок до 3–8 |
| `links-valid` | Исправить slug'и: ссылки ведут на несуществующие статьи |
| `length` | Дописать по существу, а не разбавить водой |
| `ai-markers` | Переписать абзацы со штампами |
| `duplication` | Сузить угол: текст пересказывает существующую статью |

После трёх неудачных заходов остановись и оставь файл как есть — приёмка
отправит тему на второй круг или в карантин. Это нормальный исход, а не повод
подгонять текст под проверку.


### Обложка перед приёмкой

При `gates.requireHeroImage: true` статья должна иметь `heroImage` с локальным URL `/images/...`. Файл уже существует в `public/`, его формат — JPEG, PNG или WebP, размеры ненулевые. Если есть `previewImage`, проверить его тоже. Внешний URL, отсутствующий файл и ссылка за пределы `public` не проходят блокирующий `hero-assets` гейт. При рерайте существующую пригодную обложку сохранять; не создавать новую только из-за обновления текста. Проверка метаданных не доказывает смысловое соответствие: посмотреть изображение и убедиться, что оно подходит статье. Иллюстрацию и статью передавать одним изменением репозитория.


Маркер фактчека сайта хранит дату самой проверки внутри файла: первая строка
`YYYY-MM-DD` либо `Factcheck pass: YYYY-MM-DD`; допустим также JSON с
`passed: true` и `checkedAt` (ISO UTC). Время изменения файла не доказывает
свежесть. Записывать дату только после выполненной содержательной проверки;
не продлевать её копированием старого маркера. Маркер и необходимые результаты
фактчека передавать вместе со статьёй и evidence.


Если наряд содержит `acceptedRepair`, это исправление уже принятого кандидата после отказа повторной приёмки. Прочитай существующий файл целиком и причины в `reasons`; сохрани slug, тему и целевые запросы. Исправь конкретные отказы и выполни полный ресёрч/гейты/квитанцию текущей попытки. Не снимай hold и не правь счётчики самостоятельно: повторная приёмка и календарный выпуск принадлежат pipeline. Для NEW дата соответствует текущему наряду; для REWRITE исходная pubDate сохраняется.
