# /auto-rewrite — рерайт по наряду

Вход: наряд `kind: rewrite`. Выход: обновлённый файл той же статьи.

Рерайт в автономном контуре — не «косметика раз в год», а плановая доля
выработки (`mix.rewrite` в конфиге, по умолчанию четверть). Поэтому у него
есть измеримая цель, а не «освежить текст».

## 0. Что именно устарело

В наряде — поле `reasons`. Оно определяет тип работы:

| Причина | Что делать |
|---|---|
| `reviewDate просрочен` | Проверить каждую дату, сумму и норму по первоисточнику. Изменилось — переписать раздел, не изменилось — обновить `reviewDate` |
| `не обновлялась N дн.` | То же плюс проверить, не появилось ли новых требований по теме |
| `тонкий текст` | Дописать недостающие разделы: что делать, сколько стоит, что будет при нарушении |
| `пересечение с другой статьёй` | Развести материалы: сузить угол этой, перенести пересекающийся блок в ссылку на соседа |
| `входящих ссылок N` | Найти 2–3 статьи корпуса, где тема уместна, и добавить ссылки **оттуда сюда** |
| `<дата>: <событие>` | Событие из календаря НПА близко: переписать под новые требования, вынести дедлайн в лид |

## 1. Прочитай текущий текст целиком

Плюс прошлый ресёрч, если он есть: `autopilot/research/<slug>.md`.

## 2. Проверь фактуру по первоисточникам

Каждое утверждение с датой, суммой или нормой — заново, по
`publication.pravo.gov.ru`, `consultant.ru`, `garant.ru`, `nalog.gov.ru`,
`честныйзнак.рф`. Отдельно проверь, не отменена ли норма и не сдвинут ли срок:
устаревшая дата в статье вреднее отсутствия статьи.

## 3. Правь адресно

**Не переписывай текст целиком, если причина — одна устаревшая дата.**
Тотальный рерайт стабильной статьи ломает то, что уже ранжируется, и порождает
шумный diff, в котором не видно содержательной правки.

Что сохранять: работающую структуру H2, URL (slug **не меняется**), заголовок —
если он не устарел фактически, существующие внутренние ссылки.

Что менять: устаревшие факты, недостающие разделы, битые ссылки, штампы.

## 4. Frontmatter

`slug`, `pubDate` — **не трогать**. `updatedDate` и `reviewDate` проставит
приёмка автоматически: руками их менять не нужно.

Если рерайт сильно изменил охват темы — обнови `description` и
`seo.keywords`.

## 5. Самопроверка

```bash
node autopilot/scripts/gates.mjs check --slug <slug>
```

Дальше — как в `.agents/skills/auto-write/SKILL.md`, раздел 4: до трёх заходов,
потом оставить как есть.

Отдельно проверь, что не создал дубль соседней статьи:

```bash
node autopilot/scripts/dedupe.mjs scan | head -20
```

Если ваша пара попала в `merge` — разведите материалы по углу, а не по
формулировкам: перефразированное пересечение остаётся пересечением.
