# /create-article-kontur — создание статьи (Kontur-трек)

Статьи в этом треке пишутся по Wordstat-спросу из `src/data/wordstat/discoveries/kontur/`.
Цель — информационный трафик для МСБ; каждая статья органично интегрирует продукты Контура.

Вызов: `/create-article-kontur "штраф за работу без ТС ПИоТ в 2026"`

Для публикации — `/release-article <slug>`.
Для основного (не-Kontur) трека — `/create-article`.

---

## Стадия 1 — DISCOVERY + intentMap

### 1. Подбор темы и целевого запроса

Взять тему из:
- `src/content/wiki/content-plan-2026.md` (контент-план), или
- свежего Wordstat-дифа `src/data/wordstat/discoveries/kontur/diffs/` (NEW/RISING фразы).

### 2. Проверка дублирования

Прочитать frontmatter всех `src/content/blog/*.md` и `*.mdx`.
Если пересечение по смыслу > 70% с существующей статьёй — **СТОП**, предложить варианты (объединить, дифференцировать, canonical).

### 3. Категория с НПА

Определить категорию статьи и проверить, требует ли она research-specialist:

| Категория | Обязательный НПА |
|---|---|
| `ts-piot` | ПП № 1944, 54-ФЗ |
| `markirovka` | отраслевые ПП, ст. 15.12 КоАП, ст. 171.1 УК |
| `zakonodatelstvo` | НК РФ, ТК РФ, КоАП, ФЗ |
| `egais` | ст. 14.16/14.17/14.19 КоАП, 171-ФЗ |
| `kkt` | 54-ФЗ, ст. 14.5 КоАП |

Если категория из таблицы — **research-specialist обязателен.**

### 4. Запуск research-specialist

Запустить агент `research-specialist`. Бриф сохранить:
`.claude/research/YYYY-MM-DD-slug-brief.md`

**Бриф ОБЯЗАН содержать:**
- `sources[]` — массив источников, каждый с `verified: true`
- `intentMap` — карта вопросов читателя (новое требование):

```yaml
intentMap:
  must:                            # ≥5 вопросов — все должны быть закрыты в статье
    - "Кто обязан и в какие сроки?"
    - "Какой штраф за нарушение?"
    - "Как выглядит процесс пошагово?"
    - "Сколько стоит?"
    - "Что нужно сделать прямо сейчас?"
  should:                          # желательно закрыть
    - "Есть ли исключения?"
    - "Как это работает технически?"
  could:                           # если остаётся место
    - "Какие провайдеры бывают?"
```

Логика `must`: это вопросы, с которыми читатель приходит на страницу.
Если статья не отвечает хотя бы на один — читатель уходит, позиция падает.

**Шлюз 1:**
```
[ ] Тема не дублирует существующие статьи (пересечение < 70%)?
[ ] Категория с НПА → research-brief есть; иначе пропуск разрешён?
[ ] Brief содержит ≥ 3 источника с verified: true?
[ ] intentMap.must содержит ≥ 5 вопросов?
[ ] intentMap.must покрывает штрафы/сроки/порядок действий (если применимо)?
[ ] Есть целевой поисковый запрос?
```

## Стадия 2 — WRITE

Запустить агент `content-writer` с research brief **и** intentMap.

### Требования к тексту

- 1200–2500 слов, структура: лид → 5–7 H2 → FAQ (≥ 4 вопроса) → заключение
- **Полнота по intentMap.must** — каждый вопрос из `must[]` должен быть явно закрыт в одном из H2 или FAQ
- Активный залог, прямое обращение («проверьте», «выберите»), без «предпринимателям необходимо»
- Числа цифрами, даты конкретно (01.07.2026), нет расплывчатых сроков
- **CPA-врезка по продукту** (1 абзац): взять готовый `cpaInsert` для кластера из `src/data/kontur-links.json`. Врезка вставляется естественно — там, где читатель логично спросит «как это сделать». Не в самом конце, не как реклама.

Сохранить: `src/content/blog/YYYY-MM-DD-slug.md` (или `.mdx` если нужны компоненты)

### Шлюз 2 — 7 условий

```
[ ] Файл создан, frontmatter полный, парсится без ошибок?
[ ] Тело статьи ≥ 1200 слов?
[ ] Каждый вопрос из intentMap.must закрыт в тексте?       ← ПОЛНОТА
[ ] FAQ содержит ≥ 4 вопроса?
[ ] CPA-врезка по продукту присутствует и звучит органично?
[ ] Нет стоп-слов: является, осуществляет, данный, в целях, таким образом?
[ ] check-ai риск-скор ≤ 5?                                 ← AI-маркеры
```

Для проверки check-ai:
```bash
node scripts/check-ai-markers.mjs src/content/blog/SLUG.md
```
Или запустить `/check-ai src/content/blog/SLUG.md`.
Если скор > 5 — content-writer заменяет стоп-фразы и убирает однородные абзацы.
Максимум 2 попытки; при провале — СТОП с объяснением.

## Стадия 2а — KONTUR LINKS

**Главное отличие этого трека от /create-article.**
Здесь НЕ делаем перелинковку по /blog/. Вместо этого — органичные ссылки на продукты Контура.

### Порядок

1. Прочитать `src/data/kontur-links.json`.
2. Найти кластер статьи в `clusterMap` (по значению `categories` во frontmatter).
3. Из `products[]` кластера взять соответствующие объекты продуктов.
4. Вставить в текст **≥ 3 гиперссылки на kontur.ru** с подходящим anchor-текстом из `anchors[]`.

### Правила вставки

- Ссылки вставляются в **тело статьи** (не только в cpaInsert).
- Anchor-текст — из `anchors[]` или перефразированный (не «нажмите здесь»).
- Разные ссылки — на разные страницы (`url` или `pages[].url`), не три раза одна и та же.
- Если в `pages[]` есть тематическая страница (например, `/diadoc/markirovka`) — предпочитать её главной.
- Ссылок на `/blog/ etiketka-media.ru` в этом треке **нет** — продуктовые страницы Контура заменяют внутреннюю перелинковку.

**Шлюз 2а:**
```
[ ] В тексте ≥ 3 ссылок с доменом kontur.ru?
[ ] Каждая ссылка ведёт на разную страницу?
[ ] Ни одна ссылка не ведёт на /blog/ etiketka-media.ru?
[ ] Anchor-тексты разные, не «нажмите здесь» / «по ссылке»?
```

## Стадия 2б — CALLOUTS

Прочитать статью. Найти 1–2 факта для врезок:
- `callout--penalty` — конкретные суммы штрафов
- `callout--date` — ключевая дата вступления в силу
- `callout--warning` — критическое требование (потеря лицензии, блокировка)
- `callout--tip` — пошаговый алгоритм

Вставить через `<div class="callout callout--TYPE">...</div>`.
Контент — только из текста статьи, не придумывать.

**Шлюз 2б:** не более 2 врезок; факты только из текста.

---

## Стадия 3 — FACTCHECK

1. Прогнать NPA-аудит:
   ```bash
   node scripts/factcheck/audit-npa-references.mjs --strict
   ```
   Если обнаружены ПП/Приказы/ФЗ вне whitelist `src/data/factcheck/sources.json` — исправить до запуска `/factcheck`.

2. Запустить `/factcheck <slug>`.

   Особое внимание для этого трека:
   - Штрафы указаны **по субъектам**: ИП / должностное лицо / юридическое лицо
   - Есть ли упоминание смягчения для МСП (ст. 4.1.2 КоАП — первичное нарушение МСП = ½ минимального штрафа)?
   - Если штраф крупный (> 300 тыс.) — есть ли ссылка на уголовную ответственность?

**Шлюз 3:**
```
[ ] audit-npa-references --strict зелёный?
[ ] Нет claims с confidence < 0.7 без пометки [нужна проверка]?
[ ] Штрафы указаны по субъектам (ИП / должн. / юрлицо)?
[ ] Все даты сроков подтверждены первоисточником?
[ ] Суммы штрафов соответствуют актуальной редакции КоАП?
```

При провале — таблица слабых claims → правки → повтор (≤ 2 попытки).

## Стадия 4 — РЕДПОЛИТИКА

Сверить с CLAUDE.md (разделы «Правила контента», «Стиль речи»).

**Шлюз 4:**
```
Объём:
[ ] ≥ 800 слов (сателлит) или ≥ 1500 (опорная)

Структура:
[ ] ≥ 4 H2, FAQ ≥ 3 вопросов, заключение с призывом к действию
[ ] Заголовки H2 — тема, не вопрос

Frontmatter:
[ ] title: 50–80 символов
[ ] description: 140–160 символов
[ ] reviewDate: через 6 месяцев от pubDate
[ ] tags: 4–7 штук, строчные
[ ] categories: одна из [ts-piot, kkt, markirovka, egais, zakonodatelstvo]

Стиль:
[ ] Нет запрещённых слов: является, осуществляет, в целях, таким образом, данный
[ ] Нет эмодзи, восклицательных знаков, кликбейта
[ ] Активный залог, прямое обращение к читателю
```

При провале — СТОП, варианты A (merge) / B (differentiate) / C (canonical).

## Стадия 7 — ОЦЕНКА

| Критерий | Балл |
|---|---|
| Объём ≥ 1500 слов | 1 |
| Структура: 5+ H2, FAQ, заключение | 1 |
| Kontur-ссылок ≥ 3 (kontur.ru) | 1 |
| Factcheck: нет claims < 0.7 | 2 |
| SEO: ключ в title + абзаце + H2 + description OK | 2 |
| Редполитика: нет паразитов, ToV выдержан | 1 |
| Hero-изображение (следующий шаг) | 1 |
| GEO: AI Citation score ≥ 60 | 1 |

**Шлюз 7:** итог ≥ 7/10. При меньшем — список конкретных правок, повтор.

## Правила

- Никогда не пропускать стадии.
- Максимум 2 retry на стадию — затем СТОП с объяснением блокировки.
- Не устанавливать `draft: false` — это делает `/release-article`.
- Язык — только русский.
- Конкурентов Контура в статье не упоминать; провайдеров называть только если без них невозможно описать категорию (например, список ОФД в реестре ФНС).
